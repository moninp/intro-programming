Lecture 3: Functions, Modularity, and Version Control

From Scripts to Software

Central Question

How do we turn a working program into reusable and maintainable software?

In Lecture 2, you learned to write programs that process collections of data using loops, conditionals, and data structures. Those programs worked, but they had limitations:

  • Code was difficult to reuse for similar tasks
  • Logic was scattered and hard to follow
  • No clear separation between different computational steps
  • No documentation or contracts about what the code does
  • No systematic way to track changes and improvements

Today, we’ll transform procedural scripts into well-organized, reusable functions. We’ll learn to document our code, organize it into modules, and use version control (Git) to track our work. By the end of class, you’ll be able to build small software tools that are reliable, maintainable, and ready to share with collaborators.

The key insight: Good software isn’t just about making code work—it’s about making code that you (and others) can understand, trust, and build upon.

Exercise 1: From Procedural Code to Functions

The Problem: Portfolio Analysis

You’ve been tracking daily stock prices and need to analyze returns. Here’s a working program that does the job:

# Stock prices over 10 days
prices = [150.0, 152.5, 148.0, 153.0, 155.5, 154.0, 157.5, 159.0, 156.5, 160.0]

# Calculate daily returns
returns = []
for i in range(1, len(prices)):
    daily_return = (prices[i] - prices[i-1]) / prices[i-1]
    returns.append(daily_return)

print(f"Returns: {returns[:3]}...")  # Show first 3

# Calculate average return
total_return = 0
for r in returns:
    total_return += r
average_return = total_return / len(returns)

print(f"Average return: {average_return:.4f}")

# Calculate volatility (standard deviation of returns)
squared_diffs = 0
for r in returns:
    squared_diffs += (r - average_return) ** 2
variance = squared_diffs / (len(returns) - 1)
volatility = variance ** 0.5

print(f"Volatility: {volatility:.4f}")
Returns: [0.016666666666666666, -0.029508196721311476, 0.033783783783783786]...
Average return: 0.0074
Volatility: 0.0210

This code works, but:

  • What if you need to analyze a different stock?
  • What if you want to reuse the return calculation elsewhere?
  • How do you test that the calculations are correct?
  • Can a collaborator understand what each part does?

Let’s transform this into reusable functions.

Let’s start by extracting the return calculation into a function.

  • A name that describes what it does
  • Parameters (inputs) it needs
  • A return value (output) it produces

def function_name(parameter1, parameter2):
    """Optional documentation string."""

    return result

  • Parameters in parentheses
  • Colon : ends the header
  • Indented body contains the code
  • return sends back the result

Just-in-Time Concept: Scope

Scope determines where variables are accessible:

  • Local variables: Defined inside a function, only accessible within it
  • Global variables: Defined outside functions, accessible everywhere
# Global variable
pi = 3.14159

def calculate_area(radius):
    # Local variable
    area = pi * radius ** 2
    return area

result = calculate_area(5)
print(result)
# print(area)  # Error! area is local to the function
78.53975
ImportantAvoid Modifying Global State

Functions should generally work with their parameters and return results, not modify global variables. This makes them easier to understand and test.

Interlude: Version Control with Git

Before continuing, let’s set up Git to track our work.

What is Git?

Git is a version control system that:

  • Records snapshots of your code over time
  • Lets you experiment without fear of breaking things
  • Enables collaboration with others
  • Provides a complete history of changes

Think of it as “Track Changes” for code, but much more powerful.

Key Git Concepts

Before using Git, understand these terms:

  • Repository (repo): A folder that Git tracks
  • Commit: A snapshot of your code at a specific time
  • Working directory: The current state of your files
  • Staging area: Files prepared for the next commit

The Git workflow:

Edit files → Stage changes → Commit snapshot
    ↓            ↓              ↓
Working dir → Staging area → Repository

Exercise 2.1: Writing Docstrings

Functions need documentation. Python uses docstrings—multi-line strings at the start of a function.

Just-in-Time Concept: Docstrings

def calculate_return(initial, final):

    Calculate the simple return on an investment.
    
    Parameters:
        initial: starting value
        final: ending value
        
    Returns:
        float: the return as a decimal (0.10 = 10% gain)

Exercise 2.4: Pure vs Stateful Functions

Some functions modify state; others just compute and return values.

Just-in-Time Concept: Pure Functions

A pure function:

  • Always returns the same output for the same input
  • Has no side effects (doesn’t modify anything outside itself)
  • Is easier to test and reason about
# Pure function - no side effects
def calculate_total(values):
    """Sum values and return total."""
    return sum(values)

# Stateful function - modifies a global variable
total = 0

def add_to_total(value):
    """Add value to global total."""
    global total
    total += value
    # No return value - the side effect IS the point

Your Turn: Compare Pure and Stateful

# Approach 1: Stateful (modifies a portfolio dict)
portfolio = {"cash": 10000, "stock_value": 0}

def buy_stock_stateful(shares, price):
    """Buy stock, updating global portfolio."""
    cost = shares * price
    portfolio["cash"] -= cost
    portfolio["stock_value"] += cost

buy_stock_stateful(10, 150)
print(f"Portfolio: {portfolio}")


# Approach 2: Pure (returns new portfolio)
def buy_stock_pure(portfolio, shares, price):
    """
    Buy stock, returning updated portfolio.
    
    Returns:
        dict: new portfolio with updated values
    """
    cost = shares * price
    new_portfolio = portfolio.copy()
    new_portfolio["cash"] -= cost
    new_portfolio["stock_value"] += cost
    return new_portfolio

initial_portfolio = {"cash": 10000, "stock_value": 0}
updated_portfolio = buy_stock_pure(initial_portfolio, 10, 150)
print(f"Original: {initial_portfolio}")
print(f"Updated: {updated_portfolio}")

Discussion: What are the advantages of each approach?

Pure function advantages:

  • Easier to test
  • No hidden dependencies
  • Original data preserved
  • Can run in parallel safely

Stateful function advantages:

  • Sometimes more natural
  • Can be more efficient (no copying)
  • Matches real-world mental model
TipDefault to Pure Functions

When possible, prefer pure functions. They’re easier to understand, test, and debug. Use stateful functions only when there’s a clear benefit.

Exercise 3.2: Multiple Files and Modules

As projects grow, split code into multiple files.

Just-in-Time Concept: Imports

Project structure:

portfolio_project/
    portfolio.py       # Main portfolio functions
    statistics.py      # Statistical helpers
    analysis.py        # Uses functions from other modules

statistics.py:

"""Statistical helper functions."""

def calculate_mean(values):
    """Calculate arithmetic mean."""
    return sum(values) / len(values)

def calculate_std(values):
    """Calculate sample standard deviation."""
    mean = calculate_mean(values)
    squared_diffs = sum((x - mean) ** 2 for x in values)
    return (squared_diffs / (len(values) - 1)) ** 0.5

portfolio.py:

"""Portfolio analysis functions."""

from statistics import calculate_mean, calculate_std

def calculate_sharpe_ratio(returns, risk_free_rate=0.02):
    """Calculate Sharpe ratio using statistical helpers."""
    avg_return = calculate_mean(returns)
    volatility = calculate_std(returns)
    return (avg_return - risk_free_rate) / volatility

analysis.py:

"""Main analysis script."""

from portfolio import calculate_sharpe_ratio

returns = [0.01, 0.02, -0.01, 0.03, 0.015]
sharpe = calculate_sharpe_ratio(returns)
print(f"Sharpe Ratio: {sharpe:.3f}")

Import Styles

# Import entire module
import portfolio
result = portfolio.calculate_returns(prices)

# Import specific functions
from portfolio import calculate_returns, calculate_volatility
result = calculate_returns(prices)

# Import with alias
import portfolio as pf
result = pf.calculate_returns(prices)

# Import everything (discouraged - unclear what's imported)
from portfolio import *
TipPrefer Explicit Imports

Use from module import specific_function for clarity. Avoid import * except in interactive sessions.

Synthesis: Building Reliable Software

Let’s return to our central question:

How do we turn a working program into reusable and maintainable software?

We now understand that good software requires:

1. Functions - Reusable Building Blocks

  • Package logic into named, testable units
  • Define clear parameters and return values
  • Understand scope to avoid unintended interactions

2. Documentation - Communication and Contracts

  • Write docstrings describing what functions do
  • Optionally add type hints for clarity
  • Use assertions to validate assumptions

3. Design Choices - Pure vs Stateful

  • Prefer pure functions when possible (easier to test and reason about)
  • Use stateful approaches when benefits are clear
  • Document side effects in docstrings

4. Organization - From Scripts to Modules

  • Group related functions into logical sections
  • Split large codebases into multiple files
  • Use imports to connect modules
  • Consider packages for larger projects

5. Version Control - Tracking Changes Systematically

  • Initialize Git repositories for projects
  • Commit snapshots at meaningful points
  • Write descriptive commit messages
  • Use .gitignore to exclude generated files
