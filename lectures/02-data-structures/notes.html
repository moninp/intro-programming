Lecture 2 — Data Structures, Algorithms, and Control Flow

Background Notes

1. Introduction

In Lecture 1, we considered individual computational values: integers, floating-point numbers, strings, and Boolean values. We also introduced a central idea that will recur throughout the course:

A computer does not manipulate mathematical objects directly. It executes algorithms using finite representations of information.

Today we move from individual values to collections of information and to programs that can make decisions and repeat operations.

The central questions are:

  • How should a collection of information be represented?
  • How do we access individual elements?
  • How do we add, remove, or modify information?
  • How do we associate one piece of information with another?
  • How do we express repeated computation?
  • How do we make a program behave differently depending on its input?
  • How do we turn an informal problem into a precise algorithm?

A useful way to think about today’s material is:

Information
    ↓
Data structure
    ↓
Operations on the data
    ↓
Control flow
    ↓
Algorithm
    ↓
Implementation
    ↓
Testing / validation

The choice of data structure is not merely a programming-language detail. It is part of the solution to the problem.

2. Text, Characters, and Bytes

Text looks very different from numbers to a human reader, but computers ultimately represent text using numbers and, at a lower level, bits and bytes.

A character is an abstract unit of text such as:

A
7
?
é
中

A computer must encode each character as a sequence of bits.

2.1 ASCII

The original ASCII standard assigns numeric codes to a relatively small set of characters.

For example:

ord("A")
65

returns:

65

and:

chr(65)
'A'

returns:

'A'

ASCII is useful but limited. It was designed around the needs of English-language text and contains only a small number of characters.

The ASCII standard defines codes from 0 through 127, using 7 bits. An eighth bit was sometimes used for extended character sets, but these were not standardized.

2.2 Unicode

Unicode is a much larger standard intended to provide a consistent representation for characters used by languages around the world.

A Unicode code point is a number assigned to a character.

For example:

ord("A")
65

gives the Unicode code point for A, which is 65 (the same as ASCII for compatibility), while:

ord("é")
233

gives the code point 233 for é, and:

ord("中")
20013

gives the code point 20013.

The important distinction is:

A Unicode code point identifies a character; it is not necessarily the same thing as the bytes used to store that character.

Unicode defines over 140,000 code points, organized into blocks representing different scripts and symbol systems.

2.3 UTF-8

UTF-8 is an encoding that maps Unicode characters to sequences of bytes.

For example:

"A".encode("utf-8")
b'A'

produces a one-byte representation:

b'A'

while a character such as é requires more than one byte:

"é".encode("utf-8")
b'\xc3\xa9'

produces:

b'\xc3\xa9'

The resulting object is a sequence of bytes. We can see the individual byte values:

list("é".encode("utf-8"))
[195, 169]

This shows that é requires two bytes: 195 and 169.

Characters outside the ASCII range require multiple bytes. For example:

list("中".encode("utf-8"))
[228, 184, 173]

This character requires three bytes.

We can convert those bytes back into a string:

b = "é".encode("utf-8")
b.decode("utf-8")
'é'

The distinction among character, code point, and byte is important when working with files and data.

UTF-8 has several useful properties:

  • ASCII characters (codes 0–127) are encoded using a single byte with the same value as the ASCII code;
  • characters with higher code points use multiple bytes;
  • byte sequences are self-synchronizing;
  • the encoding is efficient for text that is predominantly ASCII.

2.4 Why encodings matter

Suppose a file contains text but the program interprets the bytes using the wrong encoding. The bytes themselves have not changed; the interpretation has.

This can produce:

  • garbled text;
  • unexpected characters;
  • decoding errors;
  • corrupted data.

For example:

text = "café"
bytes_utf8 = text.encode("utf-8")

# Correct decoding
print(bytes_utf8.decode("utf-8"))

# Incorrect decoding (will likely cause an error or produce wrong characters)
try:
    print(bytes_utf8.decode("ascii"))
except UnicodeDecodeError as e:
    print(f"Error: {e}")
café
Error: 'ascii' codec can't decode byte 0xc3 in position 3: ordinal not in range(128)

This is one reason that importing data is a computational task rather than simply “opening a file.”

When working with text files, you should:

  1. Know the encoding of your input files;
  2. Specify the encoding explicitly when reading or writing;
  3. Be prepared to handle encoding errors;
  4. Use UTF-8 as the default for new files when possible.

3. Strings

A Python str is a sequence of characters.

For example:

name = "Ada Lovelace"

We can inspect its length:

len(name)
12

and access individual characters using indexing:

name[0]
'A'
name[1]
'd'
name[-1]
'e'

Python uses zero-based indexing. Thus the first element has index 0.

3.1 Indexing

If:

s = "Python"

then:

index:    0   1   2   3   4   5
          P   y   t   h   o   n

Thus:

s[0]
'P'

is "P" and:

s[5]
'n'

is "n".

Negative indices count from the end:

s[-1]
'n'

is "n", and:

s[-2]
'o'

is "o".

The relationship between positive and negative indices is:

s[-k] is equivalent to s[len(s) - k]

for positive integers \(k \leq\) len(s).

3.2 Slicing

A slice selects a portion of a sequence.

s = "Python"
s[1:4]
'yth'

returns:

'yth'

The general form is:

s[start:stop:step]

The starting index is included, but the stopping index is excluded.

This convention is extremely useful because the length of:

s[a:b]

is:

b - a

provided the indices are valid.

We can omit either endpoint:

s[:3]    # From beginning to position 3
'Pyt'
s[3:]    # From position 3 to end
'hon'
s[:]     # Entire string
'Python'

We can specify a step:

s[::2]   # Every second character
'Pto'
s[::-1]  # Reverse the string
'nohtyP'

Slicing never raises an IndexError even if indices are out of range:

s[100:200]  # Empty string
''

This behavior is useful but can also hide bugs if you expect an error when accessing invalid positions.

3.3 Strings are immutable

Python strings are immutable. Once a string object has been created, its characters cannot be changed in place.

For example, this is not allowed:

s = "Python"
s[0] = "J"

Attempting this produces:

TypeError: 'str' object does not support item assignment

Instead, we create a new string:

s = "Python"
s = "J" + s[1:]
s
'Jython'

Operations that appear to modify a string actually create new string objects:

original = "hello"
modified = original.upper()

print(f"Original: {original}")
print(f"Modified: {modified}")
print(f"Same object? {original is modified}")
Original: hello
Modified: HELLO
Same object? False

Immutability is an important concept because different data structures have different rules about whether their contents can be changed.

The advantages of immutability include:

  • strings can be safely shared between different parts of a program;
  • strings can be used as dictionary keys;
  • certain optimizations are possible;
  • reasoning about program behavior is simpler.

3.4 String methods

Strings have many useful methods:

text = "  Hello, World!  "

text.strip()      # Remove leading/trailing whitespace
'Hello, World!'
text.lower()      # Convert to lowercase
'  hello, world!  '
text.upper()      # Convert to uppercase
'  HELLO, WORLD!  '
text.replace("World", "Python")  # Replace substring
'  Hello, Python!  '
text.split(",")   # Split into list
['  Hello', ' World!  ']

Testing string properties:

"12345".isdigit()
True
"Hello".isalpha()
True
"hello".startswith("he")
True
"hello".endswith("lo")
True

Searching:

"hello world".find("world")  # Returns index or -1
6
"world" in "hello world"     # Boolean membership
True

Formatting:

name = "Alice"
age = 25
f"My name is {name} and I am {age} years old"
'My name is Alice and I am 25 years old'

These methods are particularly useful when processing real-world data, where text is often messy.

3.5 String concatenation and repetition

Strings support concatenation with +:

"Hello" + " " + "World"
'Hello World'

and repetition with *:

"Python" * 3
'PythonPythonPython'

For efficient concatenation of many strings, use "".join():

words = ["Python", "is", "powerful"]
" ".join(words)
'Python is powerful'

This is more efficient than repeated concatenation because strings are immutable.

4. Data Structures

A data structure is a way of organizing information so that a program can store it and perform useful operations on it.

Python provides several fundamental data structures:

  • lists;
  • tuples;
  • dictionaries;
  • sets.

They overlap in what they can represent, but they are designed for different purposes.

A useful question is not:

“Which data structure is best?”

but:

“What operations does my problem require, and which data structure supports those operations naturally?”

5. Lists

A list is an ordered, mutable collection.

For example:

temperatures = [72, 75, 68, 70, 74]

A list can contain values of different types:

items = [10, "hello", True, 3.14]

although in scientific and data-analysis applications, lists will often contain values of a common type.

5.1 Creating lists

Lists can be created in several ways:

# Literal notation
numbers = [1, 2, 3, 4, 5]

# Empty list
empty = []

# From another iterable
chars = list("hello")
chars
['h', 'e', 'l', 'l', 'o']
# Using a list comprehension
squares = [x**2 for x in range(5)]
squares
[0, 1, 4, 9, 16]

5.2 Indexing and slicing

Lists use the same indexing and slicing conventions as strings:

temperatures = [72, 75, 68, 70, 74]

temperatures[0]
72
temperatures[-1]
74
temperatures[1:4]
[75, 68, 70]

This is not accidental. Both strings and lists are examples of sequences.

Python sequences share common operations:

Operation Meaning
len(s) Number of elements
s[i] Element at index \(i\)
s[i:j] Slice from \(i\) to \(j\)
x in s Is \(x\) an element of \(s\)?
s + t Concatenation
s * n Repetition

5.3 Lists are mutable

Unlike strings, lists can be modified:

temperatures = [72, 75, 68, 70, 74]
temperatures[0] = 73
temperatures
[73, 75, 68, 70, 74]

We can append an element:

temperatures.append(76)
temperatures
[73, 75, 68, 70, 74, 76]

Insert at a specific position:

temperatures.insert(2, 69)
temperatures
[73, 75, 69, 68, 70, 74, 76]

Remove an element by value:

temperatures.remove(69)
temperatures
[73, 75, 68, 70, 74, 76]

Remove and return an element by index:

last = temperatures.pop()
print(f"Removed: {last}")
print(f"Remaining: {temperatures}")
Removed: 76
Remaining: [73, 75, 68, 70, 74]

Extend with another list:

temperatures.extend([77, 78])
temperatures
[73, 75, 68, 70, 74, 77, 78]

Clear all elements:

example = [1, 2, 3]
example.clear()
example
[]

5.4 List methods

Common list methods include:

numbers = [3, 1, 4, 1, 5, 9, 2, 6]

# Count occurrences
numbers.count(1)
2
# Find index of first occurrence
numbers.index(4)
2
# Sort in place
numbers.sort()
numbers
[1, 1, 2, 3, 4, 5, 6, 9]
# Reverse in place
numbers.reverse()
numbers
[9, 6, 5, 4, 3, 2, 1, 1]

Note that sort() and reverse() modify the list in place and return None.

To create a sorted copy without modifying the original:

original = [3, 1, 4, 1, 5]
sorted_copy = sorted(original)
print(f"Original: {original}")
print(f"Sorted: {sorted_copy}")
Original: [3, 1, 4, 1, 5]
Sorted: [1, 1, 3, 4, 5]

5.5 Lists and mathematical vectors

It is tempting to think of a Python list as a mathematical vector:

\[ x = \begin{pmatrix} x_1\\ x_2\\ \vdots\\ x_n \end{pmatrix}. \]

This analogy is useful, but it has limits.

A Python list is a general-purpose container. It does not automatically perform vectorized mathematical operations.

For example:

x = [1, 2, 3]
y = [4, 5, 6]

# This does NOT perform element-wise addition
x + y
[1, 2, 3, 4, 5, 6]

This concatenates the lists rather than adding corresponding elements.

For mathematical vector operations, we will later use NumPy arrays:

import numpy as np

x = np.array([1, 2, 3])
y = np.array([4, 5, 6])

x + y  # Element-wise addition: array([5, 7, 9])

This distinction will become important when we study NumPy.

5.6 Nested lists

Lists can contain other lists:

matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]

matrix[0]      # First row
[1, 2, 3]
matrix[0][1]   # First row, second column
2

This provides a simple way to represent two-dimensional data, though NumPy arrays are more efficient for numerical work.

6. Tuples

A tuple is an ordered, immutable collection.

point = (3, 4)

6.1 Creating tuples

Tuples are typically created with parentheses:

coordinates = (3.5, 7.2)
date = (2026, 1, 15)

A single-element tuple requires a trailing comma:

single = (42,)
type(single)
tuple

Without the comma, Python interprets the parentheses as grouping:

not_a_tuple = (42)
type(not_a_tuple)
int

Parentheses can sometimes be omitted:

point = 3, 4
point
(3, 4)

This is called tuple packing.

Tuple unpacking assigns elements to multiple variables:

x, y = point
print(f"x = {x}, y = {y}")
x = 3, y = 4

6.2 Tuple operations

Tuples can be indexed:

point = (3, 4)
point[0]
3

but their contents cannot be changed:

point[0] = 5  # TypeError

Tuples support the same sequence operations as lists, except those that would modify the tuple:

a = (1, 2, 3)
b = (4, 5, 6)

a + b        # Concatenation
(1, 2, 3, 4, 5, 6)
a * 2        # Repetition
(1, 2, 3, 1, 2, 3)
len(a)       # Length
3
2 in a       # Membership
True

6.3 When to use tuples

Tuples are useful when the collection represents a fixed group of values.

For example:

date = (2026, 8, 25)

might represent a year, month, and day that should not be modified.

Another common use is returning multiple values from a function:

def get_min_max(values):
    return min(values), max(values)

minimum, maximum = get_min_max([3, 1, 4, 1, 5])

The important conceptual distinction is:

Structure Ordered Mutable
list Yes Yes
tuple Yes No

Use a list when: * the collection will grow or shrink; * elements will be modified; * order matters but the collection is not conceptually “fixed.”

Use a tuple when: * the collection represents a fixed structure; * immutability is desirable (e.g., for use as a dictionary key); * the collection represents heterogeneous data that belongs together.

7. Dictionaries

A dictionary stores key-value pairs.

For example:

student = {
    "name": "Ada",
    "year": 1,
    "program": "Mathematics"
}

7.1 Creating dictionaries

Dictionaries can be created in several ways:

# Literal notation
prices = {"AAPL": 150, "GOOGL": 2800, "MSFT": 300}

# Empty dictionary
empty = {}

# Using dict()
grades = dict(Alice=85, Bob=92, Carlos=88)
grades
{'Alice': 85, 'Bob': 92, 'Carlos': 88}
# From key-value pairs
pairs = [("a", 1), ("b", 2), ("c", 3)]
dict(pairs)
{'a': 1, 'b': 2, 'c': 3}

7.2 Accessing and modifying

We retrieve a value using its key:

student = {"name": "Ada", "year": 1, "program": "Mathematics"}
student["name"]
'Ada'

We can add or modify entries:

student["year"] = 2
student["advisor"] = "Dr. Smith"
student
{'name': 'Ada', 'year': 2, 'program': 'Mathematics', 'advisor': 'Dr. Smith'}

Attempting to access a nonexistent key raises a KeyError:

student["age"]  # KeyError

The get() method provides a safer alternative:

student.get("age")         # Returns None
student.get("age", 25)     # Returns default value
25

7.3 Dictionary operations

Check if a key exists:

"name" in student
True
"age" in student
False

Remove a key:

student = {"name": "Ada", "year": 1, "program": "Mathematics"}
del student["program"]
student
{'name': 'Ada', 'year': 1}
# Remove and return value
year = student.pop("year")
print(f"Removed year: {year}")
print(f"Remaining: {student}")
Removed year: 1
Remaining: {'name': 'Ada'}

Get all keys, values, or items:

prices = {"AAPL": 150, "GOOGL": 2800, "MSFT": 300}

list(prices.keys())
['AAPL', 'GOOGL', 'MSFT']
list(prices.values())
[150, 2800, 300]
list(prices.items())
[('AAPL', 150), ('GOOGL', 2800), ('MSFT', 300)]

Iterate over a dictionary:

for ticker, price in prices.items():
    print(f"{ticker}: ${price}")
AAPL: $150
GOOGL: $2800
MSFT: $300

7.4 Dictionaries as mappings

Mathematically, a dictionary is naturally related to the idea of a mapping or function.

For example:

\[ f(\text{student ID}) = \text{student name}. \]

A dictionary can implement a finite version of this idea:

names = {
    101: "Ada",
    102: "Grace",
    103: "Alan"
}

names[102]
'Grace'

This is fundamentally different from list indexing.

A list asks:

What value is stored at position 3?

A dictionary asks:

What value is associated with this key?

7.5 Keys and values

Dictionary keys must satisfy restrictions that values do not necessarily have. In particular, keys must be hashable.

An object is hashable if: * it has a hash value that never changes during its lifetime; * it can be compared for equality.

Immutable types (int, float, str, tuple) are hashable. Mutable types (list, dict, set) are not.

valid = {(1, 2): "coordinates"}    # Tuple key: OK
invalid = {[1, 2]: "list key"}     # List key: Error

For now, the important practical idea is:

A dictionary is useful when you want to look up information by an identifier.

Examples include:

  • student ID → student record;
  • ticker symbol → price;
  • country code → country name;
  • word → frequency.

7.6 Dictionary comprehensions

Similar to list comprehensions:

squares = {x: x**2 for x in range(5)}
squares
{0: 0, 1: 1, 2: 4, 3: 9, 4: 16}
# With filtering
even_squares = {x: x**2 for x in range(10) if x % 2 == 0}
even_squares
{0: 0, 2: 4, 4: 16, 6: 36, 8: 64}

8. Sets

A set is an unordered collection of distinct elements.

countries = {"US", "UK", "France", "US"}
countries
{'France', 'UK', 'US'}

The duplicate "US" is not retained as a second element.

8.1 Creating sets

# Literal notation (for non-empty sets)
letters = {"a", "b", "c"}

# Using set()
numbers = set([1, 2, 3, 2, 1])
numbers
{1, 2, 3}
# From a string
chars = set("hello")
chars
{'e', 'h', 'l', 'o'}

Note: {} creates an empty dictionary, not an empty set. Use set() for an empty set:

empty_dict = {}
empty_set = set()

type(empty_dict), type(empty_set)
(dict, set)

8.2 Set operations

Sets are closely connected to mathematical set theory.

A = {1, 2, 3, 4}
B = {3, 4, 5, 6}

Union (\(A \cup B\)):

A | B
{1, 2, 3, 4, 5, 6}

Intersection (\(A \cap B\)):

A & B
{3, 4}

Difference (\(A \setminus B\)):

A - B
{1, 2}

Symmetric difference (\(A \triangle B\)):

A ^ B
{1, 2, 5, 6}

These correspond naturally to familiar mathematical operations.

8.3 Set methods

fruits = {"apple", "banana", "orange"}

# Add element
fruits.add("grape")
fruits
{'apple', 'banana', 'grape', 'orange'}
# Remove element (raises KeyError if not present)
fruits.remove("banana")
fruits
{'apple', 'grape', 'orange'}
# Remove element (no error if not present)
fruits.discard("kiwi")
fruits
{'apple', 'grape', 'orange'}

Test relationships:

A = {1, 2, 3}
B = {1, 2, 3, 4, 5}

A.issubset(B)
True
B.issuperset(A)
True
A.isdisjoint({4, 5, 6})
True

8.4 Sets and membership testing

Sets are especially useful when the important question is membership:

Is this element in the collection?

Membership testing for sets is very efficient (average \(O(1)\) time) compared to lists (\(O(n)\) time):

import time

# Large collection
large_list = list(range(100000))
large_set = set(range(100000))

# Test membership
target = 99999

# List membership
start = time.time()
_ = target in large_list
list_time = time.time() - start

# Set membership
start = time.time()
_ = target in large_set
set_time = time.time() - start

print(f"List: {list_time:.6f}s")
print(f"Set:  {set_time:.6f}s")
List: 0.000715s
Set:  0.000031s

8.5 Set comprehensions

squares = {x**2 for x in range(10)}
squares
{0, 1, 4, 9, 16, 25, 36, 49, 64, 81}

9. Choosing a Data Structure

Consider the following problems.

Problem A

Store the daily temperatures for a week in chronological order.

A list is a natural choice:

temperatures = [72, 75, 68, 70, 74, 77, 71]

Why? Order matters, and we may want to modify values or add new observations.

Problem B

Store the population of each state, where the state name is the natural identifier.

A dictionary is natural:

population = {
    "Virginia": 8654542,
    "Maryland": 6177224,
    "New York": 20201249
}

Why? We want to look up population by state name (key-value mapping).

Problem C

Store the unique states represented in a dataset.

A set is natural:

states = {"Virginia", "Maryland", "Virginia", "New York"}
states
{'Maryland', 'New York', 'Virginia'}

Why? We only care about presence/absence, not count or order. Duplicates are automatically eliminated.

Problem D

Store the coordinates of a point that should not change.

A tuple is reasonable:

point = (3.5, 7.2)

Why? The structure is fixed (always two coordinates) and immutability prevents accidental modification.

Problem E

Store a time series where we need both fast access by time and the ability to add new observations.

10. Control Flow

So far, our programs have executed statements in a straightforward sequence.

Real programs need to make decisions and repeat operations.

Control flow determines the order in which instructions execute.

The two fundamental ideas are:

  1. selection — choose what to do;
  2. iteration — repeat what to do.

12.3 Mathematical logic and program logic

A conditional statement is closely related to mathematical reasoning.

For example:

A program can operationalize a similar logical condition:

    ...

But a program must also specify what action to take when the condition is true or false.

The conditional statement is an imperative construct (it commands the computer to do something), while mathematical logic is typically declarative (it states what is true).

15. while Loops

A while loop repeats as long as a condition remains true.

Unlike a for loop, the number of iterations does not necessarily have to be known in advance.

15.1 while loop structure

The general form is:

while condition:
    statement
    statement
    ...

The condition is checked before each iteration. If it’s False, the loop terminates.

Example:

x = 1

    x *= 2

15.2 Infinite loops

A while loop requires care: if the condition never becomes false, the program can enter an infinite loop.

For example:

x = 1

while x < 10:
    print(x)
    # Missing: x += 1

never changes x, so the condition remains true forever.

This is an example of a programming error that is logically different from a syntax error.

Important: Always ensure the loop makes progress toward termination.

15.3 When to use while vs for

Use for when: - Iterating over a known collection - Number of iterations is predetermined - Iterating through a sequence

Use while when: - Condition-based termination - Number of iterations unknown in advance - Implementing algorithms like binary search, convergence tests, user input validation

Example of while for validation:

# Simulated user input
valid_inputs = ["invalid", "also_bad", "yes"]
input_index = 0

def get_input():
    global input_index
    result = valid_inputs[input_index]
    input_index += 1
    return result

response = get_input()

while response not in ["yes", "no"]:
    print(f"Invalid input: {response}")
    response = get_input()

print(f"Valid response: {response}")

17. List Comprehensions

Python provides a compact way to construct lists from other iterables.

For example:

This corresponds closely to the mathematical idea:

\[ \{x^2 : x=1,\ldots,5\}. \]

17.1 General syntax

The general form is:

[expression for variable in iterable]

This is equivalent to:

result = []
for variable in iterable:
    result.append(expression)

17.2 Conditional filtering

A comprehension can also contain a condition:

even_squares = [x**2 for x in range(1, 11) if x % 2 == 0]
even_squares
[4, 16, 36, 64, 100]

which produces:

[4, 16, 36, 64, 100]

The general form is:

[expression for variable in iterable if condition]

Transform strings:

['HELLO', 'WORLD', 'PYTHON']

Extract from tuples:

[1, 2, 3]

Nested comprehensions:

[1, 2, 3, 4, 5, 6, 7, 8, 9]

17.4 When to use comprehensions

List comprehensions are convenient, but they should be used when they make the logic clearer rather than simply making code shorter.

Good use:

squares = [x**2 for x in range(10)]

Harder to read:

result = [x**2 if x % 2 == 0 else x**3 for x in range(10) if x > 5]

For complex logic, a regular loop is often clearer:

result = []
for x in range(10):
    if x > 5:
        if x % 2 == 0:
            result.append(x**2)
        else:
            result.append(x**3)

18. Algorithmic Thinking

We have now encountered several examples where we started with a problem and translated it into computational steps.

That process is central to programming.

An algorithm is a finite, well-defined procedure for solving a problem.

18.1 What is an algorithm?

A useful conceptual workflow is:

Problem
   ↓
Specification
   ↓
Algorithm
   ↓
Implementation
   ↓
Testing
   ↓
Result

This is closely related to the computational workflow introduced in Lecture 1.

Problem: An informal statement of what we want to accomplish.

Specification: A precise statement of inputs, outputs, and requirements.

Algorithm: A step-by-step procedure for transforming inputs into outputs.

Implementation: Code that executes the algorithm.

Testing: Verification that the implementation produces correct results.

A useful distinction is:

A problem is not an algorithm, and an algorithm is not an implementation.

For example:

Problem: Find the largest number in a collection.

Algorithm: Scan the collection while maintaining the largest value seen so far.

Implementation: Python code that executes that algorithm.

There can be multiple algorithms for the same problem and multiple implementations of the same algorithm.

18.2 From problem to algorithm

Consider the problem:

Given a list of numbers, determine the largest value.

A natural algorithm is:

  1. Start with the first value as the current maximum.
  2. Examine the next value.
  3. If it is larger than the current maximum, make it the new maximum.
  4. Continue until every value has been examined.
  5. Return the maximum.

We can implement this directly:

numbers = [7, 3, 12, 5, 9]

current_max = numbers[0]

for number in numbers[1:]:
    if number > current_max:
        current_max = number

current_max
12

Python of course already provides:

max(numbers)
12

But implementing the algorithm ourselves is useful because it forces us to understand the underlying procedure.

18.3 Preconditions and postconditions

A precise specification includes:

Preconditions: Assumptions about the input.

Postconditions: Guarantees about the output.

For the maximum-finding problem:

Precondition: The input is a nonempty collection of comparable values.

Postcondition: The output is an element of the collection that is greater than or equal to every other element.

This style of specification will become more important when we write functions in Lecture 3.

18.4 Edge cases

Edge cases are inputs at the boundary of valid inputs or that have special properties.

For finding a maximum:

  • Empty collection (violates precondition)
  • Single element
  • All elements equal
  • Negative numbers
  • Very large collection

Good algorithm design considers edge cases explicitly rather than discovering them through failures.

One of the most useful programming skills is the ability to execute an algorithm on paper.

Consider:

20. Algorithm Complexity

Two algorithms can produce the same answer while requiring very different amounts of computational work.

20.1 Informal complexity

Suppose we have a list containing n observations.

A simple loop through the entire list requires work proportional to \(n\).

We describe this informally as:

\[ O(n) \]

For example:

numbers = list(range(100))

total = 0

for number in numbers:
    total += number

total
4950

The loop processes each observation once.

Now consider a nested loop:

numbers = list(range(10))

count = 0

for x in numbers:
    for y in numbers:
        count += 1

count
100

The inner loop runs once for every combination of x and y.

With n observations, this requires roughly:

\[ n^2 \]

operations, or:

\[ O(n^2). \]

For n = 100, this may not matter.

For n = 1,000,000, it matters enormously.

20.2 Common complexity classes

Notation Name Example
\(O(1)\) Constant Array index access
\(O(\log n)\) Logarithmic Binary search
\(O(n)\) Linear Single loop through data
\(O(n \log n)\) Linearithmic Efficient sorting
\(O(n^2)\) Quadratic Nested loop
\(O(2^n)\) Exponential Recursive Fibonacci (naive)

20.3 Why complexity matters

If an algorithm requires approximately \(n\) operations and another requires approximately \(n^2\) operations, then increasing the input size by a factor of 100 changes the work by approximately:

  • factor of 100 for the first algorithm;
  • factor of 10,000 for the second.

Thus algorithmic choices can become consequential very quickly.

Example: Finding duplicates

Algorithm 1: Compare all pairs (\(O(n^2)\))

def has_duplicate_v1(values):
    for i in range(len(values)):
        for j in range(i + 1, len(values)):
            if values[i] == values[j]:
                return True
    return False

Algorithm 2: Use a set (\(O(n)\))

def has_duplicate_v2(values):
    seen = set()
    for value in values:
        if value in seen:
            return True
        seen.add(value)
    return False

For small inputs, the difference may be negligible. For large inputs, the difference can be dramatic.

20.4 Complexity is about growth, not exact timing

Big-O notation describes how computational requirements grow with input size. It is not a stopwatch.

An algorithm with complexity \(O(n)\) can be slower than another algorithm with complexity \(O(n^2)\) for small inputs if its constant costs are much larger.

The point of complexity analysis is to reason about scaling.

Important

You do not need to become a theoretical computer scientist to write good statistical or mathematical programs.

But you should develop the habit of asking:

How does the amount of work required by this algorithm grow as my data become larger?

21. Common Programming Pitfalls

The concepts in this lecture introduce several common sources of errors.

21.1 Off-by-one errors

Because Python uses zero-based indexing and excludes the stop value in slices and range(), it is easy to write:

range(1, 10)

when you intended to include 10.

Fix: Use range(1, 11).

Always check the first and last values explicitly when working with ranges and slices.

21.2 Mutability confusion

Lists can be changed; strings and tuples cannot.

s = "hello"
s[0] = "H"  # Error: strings are immutable

lst = [1, 2, 3]
lst[0] = 10  # OK: lists are mutable

Knowing whether a data structure is mutable helps explain unexpected behavior.

Especially confusing: Mutable default arguments

def add_to_list(item, lst=[]):  # Dangerous!
    lst.append(item)
    return lst

print(add_to_list(1))  # [1]
print(add_to_list(2))  # [1, 2] -- Unexpected!

Fix: Use None as default:

def add_to_list(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

21.3 Confusing position and identity

A list is naturally indexed by position:

values[3]

A dictionary is naturally indexed by a key:

prices["AAPL"]

Choosing the wrong structure can make a problem unnecessarily difficult.

21.4 Modifying a list while iterating

numbers = [1, 2, 3, 4, 5]

for num in numbers:
    if num % 2 == 0:
        numbers.remove(num)  # Dangerous!

print(numbers)  # May not remove all even numbers

Fix: Create a new list or iterate over a copy:

numbers = [1, 2, 3, 4, 5]
numbers = [num for num in numbers if num % 2 != 0]

21.5 Infinite loops

A while loop must eventually make its condition false if termination is expected.

x = 10
while x > 0:
    print(x)
    # Missing: x -= 1

Always ensure loop variables are modified in a way that progresses toward termination.

21.6 Assuming code that runs is correct

As emphasized in Lecture 1:

The absence of an error message is not evidence that the result is correct.

A program can execute perfectly while implementing the wrong algorithm.

Always test with known inputs and edge cases.

24. Key Takeaways

You should leave this lecture understanding the following ideas.

  1. Text is represented computationally. Characters, Unicode code points, and bytes are related but distinct concepts.

  2. Strings are sequences. They can be indexed and sliced, but strings are immutable.

  3. Lists are ordered and mutable. They are useful for collections in which position matters and contents may change.

  4. Tuples are ordered and immutable. They are useful for fixed collections of related values.

  5. Dictionaries represent mappings. They associate keys with values and provide efficient lookup.

  6. Sets represent collections of distinct elements. They connect naturally to mathematical set operations and provide efficient membership testing.

  7. Data structures should be chosen based on the operations a problem requires.

  8. Conditional statements implement selection. They allow a program to make decisions based on data.

  9. Loops implement iteration. They allow an algorithm to repeat operations over data.

  10. for loops iterate over collections. Use them when the items to process are known.

  11. while loops continue until a condition changes. Use them when the number of iterations is not predetermined.

  12. range() generates integer sequences for iteration. Its stop value is excluded.

  13. List comprehensions provide a concise way to construct lists. Use them when they improve clarity.

  14. An algorithm is a precise procedure for solving a problem. It is distinct from both the problem specification and its implementation.

  15. Program state changes during execution. Tracing state by hand is an important programming and debugging skill.

  16. Computational complexity describes how resource requirements grow with input size. Algorithmic choices affect scalability.

  17. Good computational work begins with a clear problem and algorithm, not with typing code immediately.
