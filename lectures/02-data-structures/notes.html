Lecture 2 — Data Structures, Algorithms, and Control Flow

Background Notes

1. Introduction

In Lecture 1, we considered individual computational values: integers, floating-point numbers, strings, and Boolean values. We also introduced a central idea that will recur throughout the course:

A computer does not manipulate mathematical objects directly. It executes algorithms using finite representations of information.

Today we move from individual values to collections of information and to programs that can make decisions and repeat operations.

The central questions are:

  • How should a collection of information be represented?
  • How do we access individual elements?
  • How do we add, remove, or modify information?
  • How do we associate one piece of information with another?
  • How do we express repeated computation?
  • How do we make a program behave differently depending on its input?
  • How do we turn an informal problem into a precise algorithm?

A useful way to think about today’s material is:

Information
    ↓
Data structure
    ↓
Operations on the data
    ↓
Control flow
    ↓
Algorithm
    ↓
Implementation
    ↓
Testing / validation

The choice of data structure is not merely a programming-language detail. It is part of the solution to the problem.

2. Text, Characters, and Bytes

Text looks very different from numbers to a human reader, but computers ultimately represent text using numbers and, at a lower level, bits and bytes.

A character is an abstract unit of text such as:

A
7
?
é
中

A computer must encode each character as a sequence of bits.

2.1 ASCII

The original ASCII standard assigns numeric codes to a relatively small set of characters.

For example:

ord("A")

returns:

65

and:

chr(65)

returns:

'A'

ASCII is useful but limited. It was designed around the needs of English-language text and contains only a small number of characters.

2.2 Unicode

Unicode is a much larger standard intended to provide a consistent representation for characters used by languages around the world.

A Unicode code point is a number assigned to a character.

For example:

ord("A")

gives the Unicode code point for A, while:

ord("é")

gives the code point for é.

The important distinction is:

A Unicode code point identifies a character; it is not necessarily the same thing as the bytes used to store that character.

2.3 UTF-8

UTF-8 is an encoding that maps Unicode characters to sequences of bytes.

For example:

"A".encode("utf-8")

produces a one-byte representation, while a character such as é requires more than one byte:

"é".encode("utf-8")

The resulting object is a sequence of bytes.

We can convert those bytes back into a string:

b = "é".encode("utf-8")
b.decode("utf-8")

The distinction among character, code point, and byte is important when working with files and data.

2.4 Why encodings matter

Suppose a file contains text but the program interprets the bytes using the wrong encoding. The bytes themselves have not changed; the interpretation has.

This can produce:

  • garbled text;
  • unexpected characters;
  • decoding errors;
  • corrupted data.

This is one reason that importing data is a computational task rather than simply “opening a file.”

3. Strings

A Python str is a sequence of characters.

For example:

name = "Ada Lovelace"

We can inspect its length:

len(name)

and access individual characters using indexing:

name[0]
name[1]
name[-1]

Python uses zero-based indexing. Thus the first element has index 0.

3.1 Indexing

If:

s = "Python"

then:

index:    0   1   2   3   4   5
          P   y   t   h   o   n

Thus:

s[0]

is "P" and:

s[5]

is "n".

Negative indices count from the end:

s[-1]

is "n".

3.2 Slicing

A slice selects a portion of a sequence.

s[1:4]

returns:

'yth'

The general form is:

s[start:stop]

The starting index is included, but the stopping index is excluded.

This convention is extremely useful because the length of:

s[a:b]

is normally:

b - a

provided the indices are valid.

We will see the same convention with lists and other sequences.

3.3 Strings are immutable

Python strings are immutable. Once a string object has been created, its characters cannot be changed in place.

For example, this is not allowed:

s = "Python"
s[0] = "J"

Instead, we create a new string:

s = "J" + s[1:]

Immutability is an important concept because different data structures have different rules about whether their contents can be changed.

3.4 String methods

Strings have many useful methods:

text = "  Hello, World!  "

text.strip()
text.lower()
text.upper()
text.replace("World", "Python")
text.split(",")

These methods are particularly useful when processing real-world data, where text is often messy.

4. Data Structures

A data structure is a way of organizing information so that a program can store it and perform useful operations on it.

Python provides several fundamental data structures:

  • lists;
  • tuples;
  • dictionaries;
  • sets.

They overlap in what they can represent, but they are designed for different purposes.

A useful question is not:

“Which data structure is best?”

but:

“What operations does my problem require, and which data structure supports those operations naturally?”

5. Lists

A list is an ordered, mutable collection.

For example:

temperatures = [72, 75, 68, 70, 74]

A list can contain values of different types:

items = [10, "hello", True, 3.14]

although in scientific and data-analysis applications, lists will often contain values of a common type.

5.1 Indexing and slicing

Lists use the same indexing and slicing conventions as strings:

temperatures[0]
temperatures[-1]
temperatures[1:4]

This is not accidental. Both strings and lists are examples of sequences.

5.2 Lists are mutable

Unlike strings, lists can be modified.

temperatures[0] = 73

We can append an element:

temperatures.append(76)

or remove an element:

temperatures.pop()

5.3 Lists and mathematical vectors

It is tempting to think of a Python list as a mathematical vector:

\[ x = \begin{pmatrix} x_1\\ x_2\\ \vdots\\ x_n \end{pmatrix}. \]

This analogy is useful, but it has limits.

A Python list is a general-purpose container. It does not automatically perform vectorized mathematical operations.

For example:

x = [1, 2, 3]

does not behave like a NumPy vector. This distinction will become important when we study NumPy.

6. Tuples

A tuple is an ordered, immutable collection.

point = (3, 4)

Tuples can be indexed:

point[0]

but their contents cannot be changed:

point[0] = 5

will produce an error.

Tuples are useful when the collection represents a fixed group of values.

For example:

date = (2026, 8, 25)

might represent a year, month, and day.

The important conceptual distinction is:

Structure Ordered Mutable
list Yes Yes
tuple Yes No

7. Dictionaries

A dictionary stores key-value pairs.

For example:

student = {
    "name": "Ada",
    "year": 1,
    "program": "Mathematics"
}

We retrieve a value using its key:

student["name"]

This is fundamentally different from list indexing.

A list asks:

What value is stored at position 3?

A dictionary asks:

What value is associated with this key?

7.1 Dictionaries as mappings

Mathematically, a dictionary is naturally related to the idea of a mapping or function.

For example:

\[ f(\text{student ID}) = \text{student name}. \]

A dictionary can implement a finite version of this idea:

names = {
    101: "Ada",
    102: "Grace",
    103: "Alan"
}

Then:

names[102]

returns "Grace".

7.2 Keys and values

Dictionary keys must satisfy restrictions that values do not necessarily have. In particular, keys must be hashable.

For now, the important practical idea is:

A dictionary is useful when you want to look up information by an identifier.

Examples include:

  • student ID → student record;
  • ticker symbol → price;
  • country code → country name;
  • word → frequency.

8. Sets

A set is an unordered collection of distinct elements.

countries = {"US", "UK", "France", "US"}

The duplicate "US" is not retained as a second element.

Sets are closely connected to mathematical set theory.

For example:

A = {1, 2, 3}
B = {3, 4, 5}

We can compute:

A | B      # union
A & B      # intersection
A - B      # difference

These correspond naturally to familiar mathematical operations:

\[ A \cup B,\qquad A \cap B,\qquad A\setminus B. \]

Sets are especially useful when the important question is membership:

Is this element in the collection?

rather than position.

9. Choosing a Data Structure

Consider the following problems.

Problem A

Store the daily temperatures for a week in chronological order.

A list is a natural choice:

temperatures = [72, 75, 68, 70, 74, 77, 71]

Problem B

Store the population of each state, where the state name is the natural identifier.

A dictionary is natural:

population = {
    "Virginia": ...,
    "Maryland": ...,
    "New York": ...
}

Problem C

Store the unique states represented in a dataset.

A set is natural:

states = {"Virginia", "Maryland", "Virginia", "New York"}

Problem D

Store the coordinates of a point that should not change.

A tuple is reasonable:

point = (3.5, 7.2)

The important lesson is:

Data structures encode assumptions about how information will be used.

10. Control Flow

So far, our programs have executed statements in a straightforward sequence.

Real programs need to make decisions and repeat operations.

Control flow determines the order in which instructions execute.

The two fundamental ideas are:

  1. selection — choose what to do;
  2. iteration — repeat what to do.

11. Boolean Values and Comparisons

Python has two Boolean values:

True
False

Comparisons produce Boolean values.

x = 10

x > 5
x == 10
x != 7
x <= 12

The result of each expression is either True or False.

11.1 Boolean operators

Python provides:

and
or
not

For example:

x > 0 and x < 10

means that both conditions must be true.

We can also write:

0 < x < 10

which is Python’s chained-comparison syntax.

The mathematical connection is direct:

\[ 0 < x < 10. \]

But remember that a Boolean expression is evaluated by the program and produces a Boolean value.

12. Conditional Statements

An if statement allows a program to choose whether to execute a block of code.

if x > 0:
    print("positive")

We can add an alternative:

if x > 0:
    print("positive")
else:
    print("non-positive")

And multiple alternatives:

if x > 0:
    print("positive")
elif x < 0:
    print("negative")
else:
    print("zero")

Python uses indentation to define blocks of code.

This is part of the language syntax, not merely a formatting convention.

12.1 Mathematical logic and program logic

A conditional statement is closely related to mathematical reasoning.

For example:

If \(x > 0\), then \(x^2 > 0\).

A program can operationalize a similar logical condition:

if x > 0:
    ...

But a program must also specify what action to take when the condition is true or false.

13. Iteration with for

A for loop repeats a block of code for each element in a sequence or other iterable.

For example:

numbers = [2, 4, 6, 8]

for x in numbers:
    print(x)

The loop variable x takes each value in turn.

A useful way to think about the loop is:

take first element
    ↓
execute body
    ↓
take next element
    ↓
execute body
    ↓
...

13.1 Accumulating a result

One common pattern is to maintain a running total.

numbers = [2, 4, 6, 8]

total = 0

for x in numbers:
    total = total + x

print(total)

This is a computational implementation of:

\[ \sum_{i=1}^n x_i. \]

The program state changes after every iteration.

14. range()

The range() function is useful when we want to iterate over integer values.

for i in range(5):
    print(i)

produces:

0
1
2
3
4

The stop value is excluded.

We can specify a starting value:

for i in range(1, 6):
    print(i)

which produces:

1
2
3
4
5

This makes range() especially useful for implementing mathematical sums and recurrences.

For example:

total = 0

for i in range(1, 11):
    total += i

computes:

\[ \sum_{i=1}^{10} i. \]

15. while Loops

A while loop repeats as long as a condition remains true.

x = 1

while x < 10:
    print(x)
    x = x + 1

Unlike a for loop, the number of iterations does not necessarily have to be known in advance.

A while loop requires care: if the condition never becomes false, the program can enter an infinite loop.

For example:

x = 1

while x < 10:
    print(x)

never changes x, so the condition remains true.

This is an example of a programming error that is logically different from a syntax error.

16. List Comprehensions

Python provides a compact way to construct lists from other iterables.

For example:

squares = [x**2 for x in range(1, 6)]

produces:

[1, 4, 9, 16, 25]

This corresponds closely to the mathematical idea:

\[ \{x^2 : x=1,\ldots,5\}. \]

A comprehension can also contain a condition:

even_squares = [x**2 for x in range(1, 11) if x % 2 == 0]

which produces:

[4, 16, 36, 64, 100]

List comprehensions are convenient, but they should be used when they make the logic clearer rather than simply making code shorter.

17. Processing Data with Control Flow

The combination of data structures and control flow allows us to write useful programs.

Suppose we have:

temperatures = [72, 91, 68, 104, 75, 89, 63]

We might want to identify unusually high temperatures.

for temperature in temperatures:
    if temperature > 90:
        print(temperature)

This combines:

  • a list;
  • iteration;
  • a conditional;
  • a comparison.

We can construct a new list:

hot_days = [
    temperature
    for temperature in temperatures
    if temperature > 90
]

The result is:

[91, 104]

This is a simple example of a data-processing pipeline.

18. Implementing Simple Statistical Functions

Programming becomes particularly useful when we turn repeated reasoning into an algorithm.

Suppose we want to calculate the arithmetic mean of a collection:

\[ \bar{x} = \frac{1}{n}\sum_{i=1}^n x_i. \]

One direct algorithm is:

def mean(values):
    total = 0

    for x in values:
        total += x

    return total / len(values)

Although functions are formally introduced in Lecture 3, it is useful to see this example now because it illustrates how a mathematical definition becomes an algorithm.

The algorithm is:

total ← 0

for each value:
    add value to total

return total / number of values

The mathematical formula and the program express the same underlying idea, but the program must specify the sequence of operations.

19. Finding the Maximum

Consider the problem of finding the largest value in a list without using Python’s built-in max().

Mathematically, we want:

\[ \max(x_1,\ldots,x_n). \]

One algorithm is:

  1. Start with the first value as the current maximum.
  2. Examine each remaining value.
  3. If the new value is larger, replace the current maximum.
  4. Return the current maximum.

A direct implementation is:

def maximum(values):
    current_max = values[0]

    for x in values[1:]:
        if x > current_max:
            current_max = x

    return current_max

The important idea is the use of program state.

At each point in the loop, current_max represents the largest value encountered so far.

This pattern appears throughout scientific computing and data analysis.

20. Algorithms

An algorithm is a finite, well-defined procedure for solving a problem.

A useful distinction is:

A problem is not an algorithm, and an algorithm is not an implementation.

For example:

Problem: Find the largest number in a collection.

Algorithm: Scan the collection while maintaining the largest value seen so far.

Implementation: Write that algorithm in Python.

There can be multiple algorithms for the same problem and multiple implementations of the same algorithm.

21. Specification → Algorithm → Implementation

A disciplined computational workflow separates three stages.

Specification

State precisely what the program should accomplish.

For example:

Given a nonempty sequence of numbers, return its largest element.

Algorithm

Describe how to accomplish the specification.

Set current maximum to first element.

For every remaining element:
    if the element exceeds current maximum:
        replace current maximum.

Return current maximum.

Implementation

Translate the algorithm into Python:

def maximum(values):
    current_max = values[0]

    for x in values[1:]:
        if x > current_max:
            current_max = x

    return current_max

This separation becomes increasingly important as programs become larger.

22. Tracing an Algorithm

One of the most useful programming skills is the ability to execute an algorithm on paper.

Consider:

x = 5
y = 2

x = x + y
y = x + y
x = y - x

Rather than guessing the final result, construct a state table:

Statement x y
x = 5 5
y = 2 5 2
x = x + y 7 2
y = x + y 7 9
x = y - x 2 9

Tracing is useful because it forces us to reason about the program’s state rather than relying on trial and error.

It is also an important debugging skill.

23. Basic Computational Complexity

Two algorithms can produce the same answer while requiring very different amounts of computational work.

Suppose we calculate:

\[ \sum_{i=1}^{n} i^2. \]

A loop performs approximately \(n\) iterations:

total = 0

for i in range(1, n + 1):
    total += i**2

We describe this informally as having linear growth in the number of operations:

\[ O(n). \]

By contrast, the closed-form formula

\[ \frac{n(n+1)(2n+1)}{6} \]

requires a fixed number of arithmetic operations, so its computational work is approximately:

\[ O(1). \]

The difference becomes important when \(n\) is large.

23.1 Why complexity matters

We do not need advanced computer science to see the practical implication.

If an algorithm requires approximately:

\[ n \]

operations and another requires approximately:

\[ n^2 \]

operations, then increasing the input size by a factor of 100 changes the work by approximately:

  • factor of 100 for the first algorithm;
  • factor of 10,000 for the second.

Thus algorithmic choices can become consequential very quickly.

24. Complexity Is About Growth, Not Exact Timing

Big-O notation describes how computational requirements grow with input size. It is not a stopwatch.

An algorithm with complexity \(O(n)\) can be slower than another algorithm with complexity \(O(n^2)\) for small inputs if its constant costs are much larger.

Similarly, actual performance depends on:

  • hardware;
  • implementation details;
  • memory access;
  • interpreter overhead;
  • libraries;
  • input characteristics.

The point of complexity analysis is to reason about scaling.

25. A Complete Example: Filtering and Summarizing Data

Consider:

scores = [72, 91, 84, 65, 98, 77, 88]

Suppose we want to calculate the mean of scores that are at least 80.

We can first identify the qualifying observations:

selected = []

for score in scores:
    if score >= 80:
        selected.append(score)

Then calculate their mean:

total = 0

for score in selected:
    total += score

mean_score = total / len(selected)

This program contains several layers:

  1. a data structure stores the observations;
  2. control flow selects observations;
  3. another loop accumulates a quantity;
  4. the result is computed from the accumulated state.

This pattern—select, transform, summarize—will appear repeatedly later in the course when we work with pandas and R.

26. Common Programming Pitfalls

The concepts in this lecture introduce several common sources of errors.

26.1 Off-by-one errors

Because Python uses zero-based indexing and excludes the stop value in slices and range(), it is easy to write:

range(1, 10)

when you intended to include 10.

Always check the first and last values explicitly.

26.2 Mutability confusion

Lists can be changed; strings and tuples cannot.

Knowing whether a data structure is mutable helps explain unexpected behavior.

26.3 Confusing position and identity

A list is naturally indexed by position:

values[3]

A dictionary is naturally indexed by a key:

prices["AAPL"]

Choosing the wrong structure can make a problem unnecessarily difficult.

26.4 Infinite loops

A while loop must eventually make its condition false if termination is expected.

26.5 Assuming code that runs is correct

As emphasized in Lecture 1:

The absence of an error message is not evidence that the result is correct.

A program can execute perfectly while implementing the wrong algorithm.

27. Data Structures as Computational Models

The data structures introduced today can be viewed as different models for organizing information.

Structure Natural question
String What sequence of characters do I have?
List What values occur in this ordered collection?
Tuple What fixed group of values belongs together?
Dictionary What value is associated with this key?
Set Which distinct values are present?

This perspective is more useful than memorizing isolated syntax.

When encountering a new programming problem, ask:

  1. What information do I have?
  2. What operations will I need?
  3. What structure makes those operations natural?
  4. What assumptions does that structure impose?

28. Putting It All Together

Today’s material extends the computational workflow from Lecture 1.

We now have tools for representing and processing collections of information:

Problem
   ↓
Choose a representation
   ↓
Choose data structures
   ↓
Design an algorithm
   ↓
Use control flow
   ↓
Implement
   ↓
Test
   ↓
Validate

Three ideas are especially important.

1. Data structures matter

The representation of information affects what operations are easy, difficult, or efficient.

2. Control flow turns instructions into algorithms

Conditional statements and loops allow a program to respond to data and repeat computation.

3. Algorithms are more fundamental than syntax

A strong programmer should be able to describe a solution before writing Python code.

The syntax can then be treated as the language used to express the solution.

29. Key Takeaways

You should leave this lecture understanding the following ideas.

  1. Text is represented computationally. Characters, Unicode code points, and bytes are related but distinct concepts.

  2. Strings are sequences. They can be indexed and sliced, but strings are immutable.

  3. Lists are ordered and mutable. They are useful for collections in which position matters.

  4. Tuples are ordered and immutable. They are useful for fixed collections of related values.

  5. Dictionaries represent mappings. They associate keys with values.

  6. Sets represent collections of distinct elements. They connect naturally to mathematical set operations.

  7. Data structures should be chosen based on the operations a problem requires.

  8. Conditional statements implement selection. They allow a program to make decisions based on data.

  9. Loops implement iteration. They allow an algorithm to repeat operations over data.

  10. range() generates integer sequences for iteration. Its stop value is excluded.

  11. List comprehensions provide a concise way to construct lists. Concision should not come at the expense of clarity.

  12. An algorithm is a precise procedure for solving a problem. It is distinct from both the problem specification and its implementation.

  13. Program state changes during execution. Tracing state by hand is an important programming and debugging skill.

  14. Computational complexity describes how resource requirements grow with input size.

  15. Good computational work begins with a clear problem and algorithm, not with typing code immediately.

  5. What can go wrong if we choose an inappropriate data structure?
  6. How would you implement the median of a list without using a built-in sorting function?
  7. What is the difference between an algorithm and a Python program?

These questions will recur throughout the course as we move from small Python programs to numerical computing, data analysis, and statistical programming.
