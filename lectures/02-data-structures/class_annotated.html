Lecture 2: Data Structures, Algorithms, and Control Flow

From Observations to Algorithms

Central Question

Can we build a program that analyzes a collection of observations?

In Lecture 1, we learned how computers represent individual values and perform calculations. Today, we tackle a more realistic problem: analyzing collections of observations.

By the end of this lecture, you will understand how to:

  • represent collections of information using appropriate data structures;
  • design algorithms that process those collections;
  • implement conditional logic and iteration;
  • reason about edge cases and algorithmic efficiency.

2. Opening: From One Value to Many

Suppose we collect temperature measurements over several days:

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]

This is a collection of observations. What questions might we want to answer?

Pause and think: Before continuing, write down 3-4 questions you might ask about this data.

Some natural questions:

  • What was the highest temperature?
  • What was the lowest temperature?
  • What was the average temperature?
  • How many days exceeded a certain threshold?
  • Which observations seem unusual?

Each question requires us to process the collection systematically. Let’s learn how.

What Operations Do We Need?

To answer these questions computationally, we need to:

  1. Store the observations in a structured way
  2. Access individual observations
  3. Process each observation in turn
  4. Compare observations
  5. Make decisions based on conditions
  6. Accumulate results

This lecture will show you how to perform each of these operations.

Syntax Preview: Control Flow and Data Structures

Before we dive into our temperature analysis, let’s preview the Python syntax patterns you’ll encounter today. Understanding these patterns will help you recognize the similarities across different constructs.

Control Flow: The Common Pattern

All control flow structures in Python follow the same pattern:

[KEYWORD] [CONDITION]:
    [INDENTED STATEMENT(S)]
    [MORE INDENTED STATEMENTS...]
[UNINDENTED CODE CONTINUES HERE]

Key elements: - Keyword tells Python what kind of control structure - Condition (or iteration variable) determines when/how it executes - Colon (:) signals the start of the code block - Indentation (4 spaces) defines what’s inside the block - Unindenting ends the block

The Three Main Control Structures

# FOR LOOP: Iterate through a collection
for item in collection:
    # Do something with item
    print(item)

# WHILE LOOP: Repeat while condition is true  
while condition_is_true:
    # Do something
    # Update something to eventually make
    # condition false
    
# IF/ELIF/ELSE: Conditional execution
if condition1:
    # Do this if condition1 is true
elif condition2:
    # Do this if condition1 false but
    # condition2 is true
else:
    # Do this if all conditions false
1
Keyword for, iteration variable item, collection, colon
2
Indented block: executes once for each item
3
Keyword while, condition, colon
4
Indented block: executes repeatedly while condition is true
5
Keyword if, condition, colon
6
Indented block: executes only if condition1 is true
7
Keyword elif (else-if), condition, colon
8
Indented block: executes only if condition1 false but condition2 true
9
Keyword else, colon (no condition!)
10
Indented block: executes only if all previous conditions were false

Notice: Same pattern every time—keyword, condition/variable, colon, indent!

Data Structures: Know Your Delimiters

Each data structure uses different brackets:

Structure Delimiter Example When to Use
List [...] [1, 2, 3] Ordered sequence, can modify
Tuple (...) (1, 2, 3) Ordered sequence, cannot modify
Set {...} {1, 2, 3} Unique values, no order
Dict {k:v, ...} {"a": 1, "b": 2} Key-value pairs for lookup

Quick Reference

# LIST: Square brackets, ordered, mutable
temps = [15.2, 17.1, 14.8]
temps[0]          # Access: 15.2
temps.append(19)  # Modify: add to end

# TUPLE: Parentheses, ordered, immutable  
point = (10, 20)
point[0]          # Access: 10
# point[0] = 15   # ERROR: can't modify

# SET: Curly braces, unique values, no order
unique = {1, 2, 3, 2, 1}  # Becomes {1, 2, 3}
2 in unique               # Fast membership test: True

# DICT: Curly braces with colons, key-value pairs
counts = {"a": 5, "b": 3}
counts["a"]               # Access by key: 5
counts["c"] = 7           # Add new key-value pair
TipWhen You See…
  • Square brackets [] → Working with a list (ordered, can change)
  • Parentheses () → Working with a tuple (ordered, cannot change)
  • Curly braces {} → Working with a set (unique items) or dict (has colons)
  • Keyword + colon : + indent → Starting a control flow block

Whitespace matters in Python! Keep your indentation consistent (4 spaces is standard).

Exercise 1.1: Representing the Observations

Question: How should we represent a collection of temperature measurements in Python?

What We Need

We need a representation that:

  • preserves the order of observations (day 1, day 2, etc.)
  • allows us to access individual temperatures
  • can grow or shrink if needed

Python Lists

Python provides a list for exactly this purpose:

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]

A list:

  • is ordered - elements have positions
  • is mutable - we can change it
  • uses square brackets []

We can access individual elements using indexing:

temperatures[0]  # First temperature
15.2
temperatures[3]  # Fourth temperature
19.3

Python uses zero-based indexing: the first element is at position 0.

Temperatures:  [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]
Indices:         0     1     2     3     4     5     6     7

We can also index from the end:

temperatures[-1]  # Last temperature
20.5
temperatures[-2]  # Second-to-last temperature
14.1

Slicing

We can extract portions using slicing:

temperatures[0:3]  # First three temperatures
[15.2, 17.1, 14.8]
temperatures[2:5]  # Days 3-5
[14.8, 19.3, 16.5]

The general form is list[start:stop]. The start is included, but stop is excluded.

temperatures[:4]  # First four (omit start → begins at 0)
[15.2, 17.1, 14.8, 19.3]
temperatures[4:]  # From day 5 onward (omit stop → goes to end)
[16.5, 18.2, 14.1, 20.5]

Basic List Operations

How many observations do we have?

len(temperatures)
8

What if we collect a new measurement?

temperatures.append(17.8)
temperatures
[15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5, 17.8]
NoteLists Are Mutable

Unlike strings (which we’ll see later), lists can be modified after creation. This is useful when building up a collection of results.

Exercise 1.2: Finding the Maximum Temperature

Question: How can we determine the highest temperature in our collection?

Algorithm Design

Before writing code, let’s design the algorithm in plain English:

  1. Start by assuming the first temperature is the maximum
  2. Look at each remaining temperature
  3. If we find a temperature higher than our current maximum, update the maximum
  4. After examining all temperatures, return the maximum

Pause: Read through this algorithm. Does it make sense? Can you think of any problems with it?

Implementation: The for Loop

To “look at each remaining temperature,” we need iteration. Python’s for loop does exactly this:

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]

current_max = temperatures[0]

for temp in temperatures[1:]:
    if temp > current_max:
        current_max = temp

print(f"Maximum temperature: {current_max}°C")
1
Initialize our “best so far” with the first temperature
2
Loop through remaining temperatures (indices 1 through end)
3
Update our maximum only when we find a larger value
4
After examining all values, report the result 
Maximum temperature: 20.5°C

Implementation: The for Loop

To “look at each remaining temperature,” we need iteration. Python’s for loop does exactly this:

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]

current_max = temperatures[0]

for temp in temperatures[1:]:
    if temp > current_max:
        current_max = temp

print(f"Maximum temperature: {current_max}°C")
Maximum temperature: 20.5°C

Understanding the Loop

Let’s trace through the first few iterations:

Initial: current_max = 15.2

Iteration 1: temp = 17.1
  17.1 > 15.2? Yes → current_max = 17.1

Iteration 2: temp = 14.8
  14.8 > 17.1? No → current_max stays 17.1

Iteration 3: temp = 19.3
  19.3 > 17.1? Yes → current_max = 19.3

... and so on

The loop repeats the comparison for each temperature. This is why we need iteration: we’re performing the same operation multiple times.

The if Statement

The line:

if temp > current_max:
    current_max = temp

demonstrates conditional execution. The update only happens when the condition is true.

Validation

How do we know our answer is correct?

# Python has a built-in max() function
max(temperatures)
20.5

Our algorithm produces the same result. This is a simple example of validation: checking our implementation against a known answer or alternative method.

Exercise 1.3: Counting Days Above a Threshold

Question: On how many days did the temperature exceed 17°C?

Algorithm Design

  1. Start with a count of zero
  2. Examine each temperature
  3. If the temperature exceeds the threshold, increase the count
  4. Return the final count

Implementation

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]
threshold = 17.0

count = 0

for temp in temperatures:
    if temp > threshold:
        count += 1

print(f"Days above {threshold}°C: {count}")
1
Initialize accumulator at zero
2
Examine each temperature in order
3
Check if current temperature exceeds threshold
4
Increment counter only when condition is true 
Days above 17.0°C: 4

Implementation

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]
threshold = 17.0

count = 0

for temp in temperatures:
    if temp > threshold:
        count += 1

print(f"Days above {threshold}°C: {count}")
Days above 17.0°C: 4

###Accumulators

The variable count is an accumulator. It maintains state across iterations:

Before loop: count = 0

After temp = 15.2: count = 0  (not above threshold)
After temp = 17.1: count = 1  (above threshold)
After temp = 14.8: count = 1  (not above threshold)
After temp = 19.3: count = 2  (above threshold)
...

This pattern—initialize → iterate → update → return—appears frequently in computational problems.

Exercise 1.4: Computing Summary Statistics

Question: What was the average temperature?

Algorithm Design

  1. Start with a sum of zero
  2. Add each temperature to the sum
  3. Divide by the number of temperatures

Implementation

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5, 18.2, 14.1, 20.5]

total = 0
count = 0

for temp in temperatures:
    total += temp
    count += 1

average = total / count

print(f"Average temperature: {average:.1f}°C")
Average temperature: 17.0°C

Multiple Accumulators

Notice we’re maintaining two pieces of state:

  • total - the running sum
  • count - the number of observations

Edge Cases

Question: What happens if the list is empty?

temperatures = []

total = 0
count = 0

for temp in temperatures:
    total += temp
    count += 1

average = total / count  # Division by zero!
---------------------------------------------------------------------------
ZeroDivisionError                         Traceback (most recent call last)
Cell In[19], line 10
      6 for temp in temperatures:
      7     total += temp
      8     count += 1
      9 
---> 10 average = total / count  # Division by zero!

ZeroDivisionError: division by zero

This is an edge case: a situation where our algorithm fails. We need to handle it:

temperatures = []

total = 0
count = 0

for temp in temperatures:
    total += temp
    count += 1

if count > 0:
    average = total / count
    print(f"Average: {average:.1f}°C")
else:
    print("No temperatures to average")
No temperatures to average
ImportantAlways Consider Edge Cases

When designing an algorithm, ask:

  • What if the input is empty?
  • What if all values are the same?
  • What if there’s only one value?
  • What if invalid data appears?

Exercise 1.5: Representing Richer Observations

Question: What if each observation contains more than just a temperature?

Suppose we have:

Day 1: Monday, 15.2°C
Day 2: Tuesday, 17.1°C
Day 3: Wednesday, 14.8°C
...

Tuples for Fixed Pairs

A tuple represents a fixed collection of values:

observation = ("Monday", 15.2)

We can access elements:

observation[0]  # Day of week
'Monday'
observation[1]  # Temperature
15.2

But unlike lists, tuples are immutable:

observation[1] = 16.0  # Cannot modify
---------------------------------------------------------------------------
TypeError                                 Traceback (most recent call last)
Cell In[24], line 1
----> 1 observation[1] = 16.0  # Cannot modify

TypeError: 'tuple' object does not support item assignment

Lists of Tuples

We can store multiple observations:

observations = [
    ("Monday", 15.2),
    ("Tuesday", 17.1),
    ("Wednesday", 14.8),
    ("Thursday", 19.3),
    ("Friday", 16.5)
]

Now we can ask richer questions:

# Which day had the highest temperature?

max_temp = observations[0][1]
max_day = observations[0][0]

for day, temp in observations:
    if temp > max_temp:
        max_temp = temp
        max_day = day

print(f"Warmest day: {max_day} ({max_temp}°C)")
Warmest day: Thursday (19.3°C)

Notice the syntax for day, temp in observations. This is tuple unpacking: Python automatically assigns day and temp from each tuple.

Exercise 1.6: Validation and Control Flow

Question: What if we’re collecting data interactively and need to validate input?

The while Loop

A while loop repeats as long as a condition is true:

# Simulate collecting a valid temperature
temp = -100  # Invalid starting value

# In practice, this would use input(). For demonstration:
valid_temps = [150, -50, 25.3]  # The last one is valid
idx = 0

while temp < -50 or temp > 50:
    # temp = float(input("Enter temperature (-50 to 50): "))
    temp = valid_temps[idx]
    idx += 1
    
    if temp < -50 or temp > 50:
        print(f"{temp}°C is outside the valid range")

print(f"Recorded temperature: {temp}°C")
150°C is outside the valid range
Recorded temperature: -50°C

break and continue

We can exit a loop early with break:

temperatures = [15.2, 17.1, -999, 19.3, 16.5]  # -999 is a sentinel value

for temp in temperatures:
    if temp == -999:
        print("Encountered missing data marker")
        break
    print(f"Temperature: {temp}°C")
Temperature: 15.2°C
Temperature: 17.1°C
Encountered missing data marker

We can skip to the next iteration with continue:

temperatures = [15.2, 17.1, -999, 19.3, 16.5]

for temp in temperatures:
    if temp == -999:
        continue  # Skip this iteration
    print(f"Temperature: {temp}°C")
Temperature: 15.2°C
Temperature: 17.1°C
Temperature: 19.3°C
Temperature: 16.5°C

range() for Index-Based Iteration

Sometimes we need the index as well as the value:

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5]

for i in range(len(temperatures)):
    print(f"Day {i+1}: {temperatures[i]}°C")
Day 1: 15.2°C
Day 2: 17.1°C
Day 3: 14.8°C
Day 4: 19.3°C
Day 5: 16.5°C

range(n) generates numbers from 0 to n-1:

list(range(5))
[0, 1, 2, 3, 4]
list(range(2, 8))  # Start and stop
[2, 3, 4, 5, 6, 7]
list(range(0, 10, 2))  # Start, stop, step
[0, 2, 4, 6, 8]

List Comprehensions

For simple transformations, Python offers list comprehensions:

temperatures = [15.2, 17.1, 14.8, 19.3, 16.5]

# Convert to Fahrenheit
fahrenheit = [(temp * 9/5) + 32 for temp in temperatures]
fahrenheit
[59.36, 62.78, 58.64, 66.74000000000001, 61.7]

With filtering:

# Only warm days
warm = [temp for temp in temperatures if temp > 16]
warm
[17.1, 19.3, 16.5]
NoteWhen to Use Comprehensions

List comprehensions are elegant for simple transformations. But if the logic is complex, a regular loop is often clearer.

Readability matters more than brevity.

Question: What data structure makes sense?

Python Dictionaries

A dictionary stores key-value pairs:

counts = {"a": 3, "b": 1, "c": 2}

We access values by key:

text = "banana"

counts = {}

for char in text:

Exercise 2.4: What’s Actually Stored?

We’ve been working with strings like "Python". But what does the computer actually store?

Characters and Code Points

Each character has a numerical code point:

ord("A")  # Get code point
65
ord("a")
97
chr(65)  # Get character from code point
'A'

This is Unicode: a system that assigns numbers to characters.

Encoding to Bytes

The computer stores these as bytes:

text = "Hello"
encoded = text.encode("utf-8")
encoded
b'Hello'
list(encoded)  # Show individual bytes
[72, 101, 108, 108, 111]

For non-ASCII characters:

text = "café"
encoded = text.encode("utf-8")
list(encoded)
[99, 97, 102, 195, 169]

The é requires multiple bytes to store.

Decoding

We can convert bytes back to text:

encoded.decode("utf-8")
'café'
NoteEncoding Matters

Different encoding schemes (UTF-8, ASCII, etc.) represent characters differently. This becomes important when:

  • Reading files from different sources
  • Working with web data
  • Handling international text

The key conceptual point: text is ultimately represented as binary data, just like numbers.

Which Is Better?

Let’s think about the computational work:

Algorithm 1:

  • For each of n values, check against up to n other values
  • Total comparisons: roughly n²/2
  • As n grows, work grows quadratically: O(n²)

Algorithm 2:

  • For each of n values, check set membership (fast) and add to set
  • Total operations: roughly n
  • As n grows, work grows linearly: O(n)

Demonstration

import time

def algorithm1(values):
    """Compare all pairs"""
    for i in range(len(values)):
        for j in range(i + 1, len(values)):
            if values[i] == values[j]:
                return True
    return False

def algorithm2(values):
    """Use a set"""
    seen = set()
    for value in values:
        if value in seen:
            return True
        seen.add(value)
    return False

# Test with different sizes
sizes = [100, 200, 400, 800]

for n in sizes:
    values = list(range(n))  # No duplicates (worst case)
    
    start = time.time()
    algorithm1(values)
    time1 = time.time() - start
    
    start = time.time()
    algorithm2(values)
    time2 = time.time() - start
    
    print(f"n={n:4d}: Algorithm 1: {time1:.4f}s  Algorithm 2: {time2:.6f}s")
n= 100: Algorithm 1: 0.0001s  Algorithm 2: 0.000006s
n= 200: Algorithm 1: 0.0004s  Algorithm 2: 0.000008s
n= 400: Algorithm 1: 0.0020s  Algorithm 2: 0.000015s
n= 800: Algorithm 1: 0.0093s  Algorithm 2: 0.000028s

Notice how Algorithm 1’s time grows rapidly while Algorithm 2 remains fast.

Synthesis: From Exercise to Program

Let’s return to the central question:

Can we build a program that analyzes a collection of observations?

We now know the answer is yes, and we understand what it requires:

1. Representation

Choose a data structure based on the operations needed:

Structure Use when you need
List Ordered sequence, indexing, mutation
Tuple Fixed, immutable groups
Dict Key-value associations, counting, lookup
Set Uniqueness, membership testing

2. Algorithm

Design the procedure:

  • What are the inputs?
  • What is the output?
  • What steps transform input to output?
  • What state must be maintained?
  • What are the edge cases?

3. Implementation

Express the algorithm using:

  • for loops for iterating through collections
  • while loops for validation or unknown iteration count
  • if/elif/else for conditional logic
  • Accumulators for maintaining state
  • Appropriate data structures

4. Validation

Check correctness:

  • Test with known cases
  • Check edge cases (empty input, single value, duplicates)
  • Compare with alternative methods
  • Verify assumptions (preconditions/postconditions)

5. Efficiency

Consider algorithmic complexity:

  • How does work grow with input size?
  • Can a different data structure improve performance?
  • Are there unnecessary repeated operations?

This workflow—represent → design → implement → validate → refine—applies to computational problems throughout statistics, mathematics, and science.
