First Steps with Python

Introduction

In this tutorial, we’ll guide you through setting up a complete Python development environment. By the end of this session, you’ll understand:

  • What Python is and how to install it on your system
  • Running Python interactively from the terminal
  • Running Python scripts from files
  • What an IDE (Integrated Development Environment) is and why it’s useful
  • Installing and using Spyder as your Python IDE
  • Taking a tour of Spyder and understanding its key features
  • Creating virtual environments to manage project dependencies
  • Connecting virtual environments to Spyder and switching between them
  • Understanding package isolation across different environments
  • Basic troubleshooting for common issues

Think of this as building your Python toolkit from the ground up. We’ll start simple (running Python from the command line) and progressively build toward a professional development setup with virtual environments and an IDE.

NoteWhy Virtual Environments?

As you work on different projects, you’ll need different packages and potentially different versions of the same package. Virtual environments allow you to create isolated Python installations for each project, preventing conflicts and making your work reproducible.

1.3 Running Python Interactively

One of the most powerful ways to learn Python is through the interactive interpreter (also called the REPL - Read-Eval-Print Loop). This lets you type Python commands one at a time and see immediate results.

  • Windows
  • Mac/Linux

In PowerShell, type:

python

In Terminal, type:

python3

You should see something like this:

Python 3.12.0 (main, Oct 10 2023, 12:00:00)
[GCC 9.4.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>>

The >>> is the Python prompt, waiting for your input.

1.4 Exploring Basic Python Concepts

Now let’s explore some fundamental Python concepts. Type each command after the >>> prompt.

Variables and Dynamic Typing

Python uses dynamic typing, meaning variables can hold different types of data at different times:

# Integer
x = 10
type(x)  # Returns: <class 'int'>
# String
x = 'phil'
type(x)  # Returns: <class 'str'>
# Float
x = 10.0
type(x)  # Returns: <class 'float'>
# Boolean (note: must be capitalized!)
x = True
type(x)  # Returns: <class 'bool'>
ImportantPython is Case-Sensitive!

Try typing x = TrUe (wrong capitalization):

x = TrUe  # This will raise a NameError!

This produces an error because Python expects True with capital T and lowercase r, u, e.

Working with Multiple Variables

x = 10
y = 20

Checking Your Workspace

The dir() function shows all variables and functions currently in your workspace:

dir()

You’ll see a list that includes x and y along with some built-in names.

Importing Modules

Python’s power comes from its extensive library of modules. Let’s use the math module:

import math
math.sin(0)  # Returns: 0.0

The sine of 0 radians is 0 (as expected from trigonometry).

Exiting Python

To exit the interactive interpreter:

quit()

Or press Ctrl+D (Mac/Linux) or Ctrl+Z then Enter (Windows).

TipWhat We Just Learned
  • Python uses dynamic typing (variables can change types)
  • type() tells us what kind of data we have
  • dir() shows what’s in our workspace
  • Python has many built-in modules like math
  • Python is case-sensitive!

2.3 Write Your First Script

In the text editor, type the following Python code:

# first_script.py
# My first Python script!

print("Hello, Python world!")
print("=" * 40)  # Print a line of 40 equals signs

# Define some variables
name = "Student"
course = "Math 5200"
year = 2026

# Print formatted information
print(f"Welcome, {name}!")
print(f"Course: {course}")
print(f"Year: {year}")
print("=" * 40)

# Do some calculations
x = 10
y = 20
sum_result = x + y
product = x * y

print(f"{x} + {y} = {sum_result}")
print(f"{x} × {y} = {product}")

# Import a module and use it
import math
angle_rad = math.pi / 4  # 45 degrees in radians
sin_value = math.sin(angle_rad)

print("=" * 40)
print(f"sin(π/4) = {sin_value:.4f}")
print("Script complete!")

Save the file and close the editor.

TipUnderstanding the Code
  • print() displays text to the console
  • "=" * 40 repeats the equals sign 40 times (string multiplication)
  • f"..." creates an f-string (formatted string) where {variable} is replaced with the variable’s value
  • {sin_value:.4f} formats the number to 4 decimal places

Step 4: Create Virtual Environment and Use with Spyder

Now we’ll create our first virtual environment. Think of a virtual environment as a separate Python installation specific to a project, with its own set of packages.

4.1 Understanding Virtual Environments

NoteWhy Virtual Environments?

Imagine you have: - Project A that needs numpy version 1.24 - Project B that needs numpy version 1.26 (with breaking changes)

Without virtual environments, you can only have one version installed globally. With virtual environments, each project gets its own Python installation with its own packages!

4.2 Create Your First Virtual Environment

Let’s create a virtual environment called env1.

  • Windows
  • Mac/Linux
# Navigate to your course folder
cd $HOME\Documents\math5200

# Create a virtual environment named 'env1'
python -m venv env1

# Activate the virtual environment
.\env1\Scripts\Activate.ps1
WarningPowerShell Execution Policy

If you get an error about execution policies, run:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Then try activating again.

# Navigate to your course folder
cd ~/Documents/math5200

# Create a virtual environment named 'env1'
python3 -m venv env1

# Activate the virtual environment
source env1/bin/activate

When activated, you’ll see (env1) at the beginning of your command prompt:

(env1) PS C:\Users\YourName\Documents\math5200>

This indicates you’re working inside the virtual environment.

4.3 Install Required Packages

Now we’ll install packages specifically for this virtual environment.

# Upgrade pip (good practice)
python -m pip install --upgrade pip

# Install spyder-kernels (required to connect Spyder to this environment)
pip install spyder-kernels
NoteWhat is spyder-kernels?

spyder-kernels is a bridge that allows Spyder (running globally) to execute code in your virtual environment. Without it, Spyder can’t “see” your environment’s Python installation.

4.4 Find Your Virtual Environment’s Python Path

We need to tell Spyder where this environment’s Python is located. Let’s find the path:

  • Windows
  • Mac/Linux

(Get-Command python).Path

Or:

python -c "import sys; print(sys.executable)"

This will output something like:

C:\Users\YourName\Documents\math5200\env1\Scripts\python.exe

Copy this path - you’ll need it in the next step!

# While env1 is activated
which python3

Or:

python3 -c "import sys; print(sys.executable)"

This will output something like:

/Users/YourName/Documents/math5200/env1/bin/python3

Copy this path - you’ll need it in the next step!

TipFinding All Python Installations

To see all Python installations on your system:

Windows (PowerShell):

Mac/Linux:

4.5 Connect Spyder to Your Virtual Environment

Now let’s configure Spyder to use our env1 virtual environment.

ImportantStep-by-Step Instructions

Follow these steps carefully. We’ll make the configuration persistent so it applies every time you start a new console.

  1. Open Spyder (if not already open)

  2. Go to Preferences:

    • Windows/Linux: Tools → Preferences
    • Mac: Python → Preferences (or Spyder → Preferences)
ImportantMac Users: Finding Preferences

On Mac, Preferences is not under Tools! Instead:

  • Menu bar (top of screen): Spyder → Preferences… OR Python → Preferences…
  • Keyboard shortcut: ⌘, (Command + comma)
  • Can’t find it? Help → Spyder tutorial → search “Preferences” → Enter

The location is in the menu bar at the top of your screen, not in Spyder’s window!

  1. Navigate to Python Interpreter:
    • In the left sidebar, click Python interpreter
  2. Select “Use the following Python interpreter”:
    • Click the radio button for “Use the following Python interpreter”
    • Click the text box or the folder icon to browse
  3. Paste Your Python Path:
    • Paste the path you copied earlier (e.g., C:\Users\YourName\Documents\math5200\env1\Scripts\python.exe on Windows)
    • Click OK or Apply
  4. Restart Spyder:
    • Close and reopen Spyder for changes to take effect
    • Alternatively, go to Consoles → Restart kernel in an open console

After restarting, you can verify which Python Spyder is using by typing in the IPython console:

import sys
print(sys.executable)

You should see the path to your env1 Python!

4.5.1 Troubleshooting: Spyder-Kernels Version Compatibility

WarningCommon Issue: Version Mismatch

When you first try to use Spyder with your virtual environment, you might see an error message like:

The Python environment or installation whose interpreter is located at

    C:\Users\YourName\Documents\math5200\env1\Scripts\python.exe

doesn't have the spyder-kernels module or the right version of it installed 
(>= 2.4.0 and < 2.5.0). Without this module is not possible for Spyder to 
create a console for you.

You can install it by activating your environment (if necessary) and 
then running in a system terminal:

    conda install spyder-kernels=2.4
or
    pip install spyder-kernels==2.4.*

Don’t panic! This is completely normal and easy to fix.

Why Does This Happen?

The issue occurs because Spyder (the IDE you installed globally) and spyder-kernels (the bridge you installed in your virtual environment) need to have compatible versions.

Think of it like this: - Spyder is like a remote control (installed globally on your system) - spyder-kernels is like a receiver (installed in each virtual environment) - The remote and receiver need to “speak the same language” (compatible versions)

When you install Spyder globally, it expects a specific range of spyder-kernels versions. If you simply run pip install spyder-kernels in your virtual environment, you might get the latest version, which could be too new or too old for your version of Spyder.

How to Fix It

The error message helpfully tells you exactly what to do! Follow these steps:

Step 1: Note the required version from the error message

Look for the version requirement in the error. It will say something like: - >= 2.4.0 and < 2.5.0 (meaning version 2.4.x) - Or it might directly suggest: spyder-kernels==2.4.*

Step 2: Activate your virtual environment (if not already active)

  • Windows
  • Mac/Linux
cd $HOME\Documents\math5200
.\env1\Scripts\Activate.ps1
cd ~/Documents/math5200
source env1/bin/activate

Step 3: Install the compatible version

Use the exact command suggested in the error message. For example:

# Install the specific version range that Spyder needs
pip install spyder-kernels==2.4.*

Or if a more specific version is suggested:

pip install spyder-kernels==2.4.3

The ==2.4.* syntax means “install any version that is 2.4.something” (like 2.4.0, 2.4.1, 2.4.3, etc.)

Step 4: Restart Spyder or the kernel

  • Close and reopen Spyder, OR
  • In Spyder: Consoles → Restart kernel (or press Ctrl+.)

The error should now be gone!

Checking Versions

You can check which versions you have installed:

Check Spyder version:

In Spyder’s console (or any Python console):

import spyder
print(spyder.__version__)

Or from the terminal:

# Windows
spyder --version

# Mac/Linux
spyder --version

Check spyder-kernels version (in your virtual environment):

# Make sure your virtual environment is activated first!
pip show spyder-kernels

This shows you detailed information including the version number.

Preventing This Issue

To avoid version mismatches in the future:

Option 1: Install the compatible version immediately (Recommended)

When setting up a new virtual environment, install the compatible spyder-kernels version right away:

# Activate your environment first
# Then check what version your global Spyder needs
# For example, if you have Spyder 5.4.x:
pip install spyder-kernels==2.4.*

Option 2: Keep Spyder updated

Periodically update your global Spyder installation:

pip install --upgrade spyder

Then update spyder-kernels in your virtual environments to match.

Option 3: Note the version in your documentation

When you create a requirements.txt file, include the specific spyder-kernels version:

spyder-kernels==2.4.3
numpy==1.24.0
# ... other packages

This ensures anyone recreating your environment gets the compatible version.

Compatibility Reference

Here’s a general guide (check Spyder’s documentation for the latest):

Spyder Version Compatible spyder-kernels
5.4.x 2.4.x
5.5.x 2.5.x
6.0.x (beta) 3.0.x
NoteWhy Not Install Spyder in Each Virtual Environment?

You might wonder: “Why not just install Spyder itself in each virtual environment?”

You can do this! Some people prefer this approach because it guarantees compatibility. However:

Pros of global Spyder: - Only one installation to maintain - Less disk space used - Same familiar Spyder interface across all projects

Pros of per-environment Spyder: - Perfect version matching every time - Complete project isolation - Can use different Spyder versions for different projects

For this course, we use the global approach because it’s simpler to manage, but both are valid!

Still Having Issues?

If you’ve installed the correct spyder-kernels version and still see errors:

  1. Completely restart Spyder (close and reopen, not just restart kernel)

  2. Verify the environment path in Preferences → Python interpreter

  3. Check that the environment is truly activated when you install packages

  4. Try removing and reinstalling spyder-kernels:

    pip uninstall spyder-kernels
pip install spyder-kernels==2.4.*

  5. Check for conflicting installations:

    # In your virtual environment
import sys
print(sys.executable)  # Should point to your virtual environment

import spyder_kernels
print(spyder_kernels.__file__)  # Should be inside your virtual environment

4.6 Tour of Spyder

Now that Spyder is connected to your virtual environment, let’s explore its interface.

Spyder has several key panels:

1. Editor (Left side)

  • This is where you write and edit your Python scripts
  • Multiple files can be open in tabs
  • Features syntax highlighting, code completion, and real-time error checking

2. IPython Console (Bottom right)

  • Interactive Python console (like the terminal, but better!)
  • Results appear immediately after you type commands
  • Access to command history
  • Rich output (plots, tables, etc.)

3. Variable Explorer (Top right)

  • Shows all variables currently in memory
  • Double-click to view/edit variable contents
  • See data types, sizes, and values at a glance
  • This is incredibly useful for debugging and understanding program state!

4. Help/Plots Pane (Top right, tabs)

  • Help: Documentation for functions/objects (press Ctrl+I when cursor is on a function)
  • Plots: Displays matplotlib plots inline
  • Files: Browse your file system

4.7 Working in Spyder

Let’s write and run some code in Spyder.

Using the Editor

  1. In the Editor panel, create a new file (File → New File or Ctrl+N)
  2. Type the following code:
# spyder_demo.py
# Demonstrating Spyder features

import math

# Create some variables
numbers = [1, 2, 3, 4, 5]
squared = [x**2 for x in numbers]

# Calculate statistics
total = sum(numbers)
mean = total / len(numbers)
std_dev = math.sqrt(sum((x - mean)**2 for x in numbers) / len(numbers))

# Print results
print(f"Numbers: {numbers}")
print(f"Squared: {squared}")
print(f"Mean: {mean}")
print(f"Standard Deviation: {std_dev:.3f}")

# Create a dictionary
data = {
    'numbers': numbers,
    'squared': squared,
    'mean': mean,
    'std_dev': std_dev
}

print("\nData dictionary created!")
print("Check the Variable Explorer →")

  1. Save the file (File → Save or Ctrl+S) in your math5200/src folder as spyder_demo.py

  2. Run the file:

    • Click the green “Run” triangle button in the toolbar, OR
    • Press F5, OR
    • Go to Run → Run

Observe the Results

After running:

  1. Console: See the printed output
  2. Variable Explorer: See all your variables (numbers, squared, total, mean, std_dev, data)
    • Click on numbers to see the list
    • Click on data to see the dictionary contents
TipVariable Explorer Power

The Variable Explorer is one of Spyder’s best features! You can: - See all variables and their types/sizes - Double-click to view contents in detail - Edit simple variables directly - Export data to files

Using the Console Interactively

In the IPython Console, you can interact with the variables from your script:

# These variables exist because we ran the script
numbers
# Output: [1, 2, 3, 4, 5]

squared[2]
# Output: 9

data['mean']
# Output: 3.0

4.9 Restart Kernel and Use numpy

After installing a new package, you need to restart the Python kernel to use it.

  1. In Spyder, go to Consoles → Restart kernel (or press Ctrl+.)
  2. In the console, type:
import numpy as np

# Create a numpy array
arr = np.array([1, 2, 3, 4, 5])
print(arr)
print(f"Array type: {type(arr)}")

# Perform vectorized operations
squared = arr ** 2
print(f"Squared: {squared}")

# Numpy has lots of mathematical functions
mean = np.mean(arr)
std = np.std(arr)
print(f"Mean: {mean}, Std Dev: {std}")
TipWhy Restart the Kernel?

Python loads modules into memory when you first import them. To see newly installed packages, you need to restart the Python process (kernel) so it can find and load the new packages.

Basic Troubleshooting

Here are solutions to common issues you might encounter:

Issue 1: “python: command not found” or “‘python’ is not recognized”

Solution: Python wasn’t added to your PATH during installation.

  • Windows: Uninstall and reinstall Python, making sure to check “Add Python to PATH”
  • Mac/Linux: Use python3 instead of python, or create an alias

Issue 2: Can’t activate virtual environment on Windows (Execution Policy error)

Solution:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Issue 3: Spyder won’t start or crashes

Solutions: - Make sure you installed spyder-kernels in your virtual environment - Try resetting Spyder’s settings: Help → Reset Spyder to factory defaults - Check Python version compatibility with your Spyder version

Issue 4: Spyder doesn’t see newly installed packages

Solution: Restart the kernel (Consoles → Restart kernel or Ctrl+.)

Issue 5: “ModuleNotFoundError” even though package is installed

Solutions: - Verify you’re using the correct virtual environment in Spyder (check with import sys; print(sys.executable)) - Make sure the package is installed in the active environment: pip list - Restart the kernel after installing packages

Issue 6: Can’t find the Python executable path

Solution: Use Python itself to tell you:

  • Windows
  • Mac/Linux
python -c "import sys; print(sys.executable)"
python3 -c "import sys; print(sys.executable)"

Issue 7: Multiple Python versions installed - confusion about which is which

Solution:

Windows:

py -0p  # Lists all Python installations

Mac/Linux:

which -a python python3
ls -l /usr/bin/python*
ls -l /usr/local/bin/python*

Issue 8: Virtual environment activated but wrong Python still running

Solution: - Deactivate and reactivate the environment - Check with which python (Mac/Linux) or (Get-Command python).Path (Windows) - Make sure you’re using the activation script from the correct environment folder
