Lecture 5 — Data, Files, and the Path from Raw Information to Analysis

Background Notes

1. Introduction

Data rarely arrives in analysis-ready form. Raw observations sit in files with cryptic encodings, inconsistent formats, missing values, unit errors, and timestamps that span multiple conventions. Before any statistical analysis, visualization, or modeling can occur, you must transform this raw information into structured data that accurately represents the phenomena you’re studying.

This transformation process—often called data wrangling, munging, or preprocessing—occupies 50-80% of a data scientist’s time. It’s not glamorous work, but it’s where scientific reasoning begins. Every decision you make about how to handle missing values, which observations to exclude, how to categorize continuous variables, and what derived quantities to compute embodies assumptions about your scientific question. These decisions shape the conclusions you can draw.

The tools you use matter enormously. For decades, scientists cleaned data in spreadsheets, clicking cells one at a time, with no record of what was changed or why. Modern data science demands reproducibility: another scientist should be able to obtain your input data, run your code, and get identical results. This requires treating data processing as programming—writing scripts that transform raw inputs into analysis-ready outputs in a documented, repeatable way.

Python’s pandas library has become the standard tool for this work. Built on NumPy’s efficient array operations, pandas provides data structures (Series and DataFrames) specifically designed for labeled, heterogeneous tabular data. It combines the statistical data analysis capabilities of R with the general-purpose programming power of Python. Whether you’re processing hurricane observations, analyzing gene expression data, or studying financial markets, pandas provides consistent patterns for reading files, inspecting data quality, cleaning inconsistencies, grouping observations, merging datasets, and computing summaries.

But tools alone aren’t enough. You must develop habits of skepticism and validation. When you load a dataset, your first questions should be: Where did this come from? How was it collected? What might be wrong with it? What assumptions am I making when I process it? This lecture teaches not just pandas syntax, but a methodology for moving systematically from raw information to trustworthy analysis-ready data, making your assumptions explicit and your process reproducible.

2. Files and Data Formats

2.1 Text Files and Encodings

At the most fundamental level, data files are sequences of bytes stored on disk. Text files encode these bytes as characters using a character encoding scheme. The most important encoding today is UTF-8, which can represent all Unicode characters while remaining backward-compatible with ASCII.

# Writing text to a file
text_data = """This is sample text.
It spans multiple lines.
UTF-8 handles special characters: é, ñ, 中文"""

# Write to file
with open('sample.txt', 'w', encoding='utf-8') as f:
    f.write(text_data)

# Read from file
with open('sample.txt', 'r', encoding='utf-8') as f:
    content = f.read()
    print(content)
This is sample text.
It spans multiple lines.
UTF-8 handles special characters: é, ñ, 中文

The with statement ensures files are properly closed even if errors occur. This is Python’s context manager syntax—when the indented block ends, the file automatically closes. Without it, you must manually call f.close(), which is error-prone because it won’t execute if an exception occurs earlier.

File modes: - 'r': Read (default) - 'w': Write (overwrites existing file) - 'a': Append (adds to end of existing file) - 'r+': Read and write - 'b': Binary mode (e.g., 'rb' for reading binary data)

Reading methods: - .read(): Returns entire file as single string - .readline(): Returns next line including newline character - .readlines(): Returns list of all lines - Iteration: for line in f: reads line by line (memory efficient)

# Writing multiple lines
lines = ['First line\n', 'Second line\n', 'Third line\n']
with open('multiline.txt', 'w') as f:
    f.writelines(lines)

# Reading line by line (memory efficient for large files)
with open('multiline.txt', 'r') as f:
    for line_num, line in enumerate(f, start=1):
        print(f"Line {line_num}: {line.strip()}")  # .strip() removes newline

3. Data Structures and Types

3.1 Structured vs Unstructured Data

Structured data fits into tables with rows and columns. Each column has a consistent type, and rows represent observations. Examples: CSV files, SQL databases, spreadsheets.

Semi-structured data has organization but doesn’t fit cleanly into tables. Examples: JSON with nested objects, XML, log files with varying formats.

Unstructured data lacks predefined organization. Examples: plain text, images, audio, video.

Most scientific data is structured or semi-structured. This course focuses on structured data processed with pandas.

13. Key Takeaways

  1. Data management is scientific reasoning: Every decision about handling missing values, categorizing variables, or filtering outliers embodies assumptions that affect conclusions.

  2. Reproducibility requires scripting: Manual data manipulation in spreadsheets is not reproducible. All data processing must be coded so others can reproduce your results.

  3. CSV is simple but has complexities: Embedded commas, quotes, different delimiters, and missing value codes require careful handling with pd.read_csv() parameters.

  4. JSON handles hierarchical data: Use JSON for nested structures, configurations, and API responses. Convert to DataFrames for analysis.

  5. pandas DataFrames are labeled arrays: Unlike NumPy arrays, DataFrames have column names and row indices, making data more self-documenting.

  6. Series are 1D, DataFrames are 2D: A DataFrame column is a Series. Selecting a single column returns a Series; selecting multiple columns returns a DataFrame.

  7. .loc[] uses labels, .iloc[] uses positions: Bracket indexing df[...] selects columns or rows based on boolean masks. Use .loc and .iloc for explicit row/column selection.

  8. Boolean indexing filters data: Create boolean masks with comparisons (df['col'] > 5) and filter with df[mask]. Combine conditions with & (and), | (or), ~ (not).

  9. Missing data requires decisions: Dropping, filling, or flagging missing values each has implications. Document your choice and rationale.

  10. Data types matter: Check types with .dtypes. Convert dates with pd.to_datetime(), numbers with pd.to_numeric(), and use category type for repeated values.

  11. GroupBy implements split-apply-combine: Group by categorical variables, apply aggregation functions, and combine results. This is fundamental to data analysis.

  12. Merging combines datasets: Use pd.merge() with appropriate join type (inner, left, right, outer) to combine data from multiple sources.

  13. Datetime operations extract temporal features: Use .dt accessor for year, month, day, day_of_week, etc. This enables temporal analysis.

  14. Vectorized operations are fast: Avoid loops when possible. Use pandas/NumPy vectorized operations for speed and readability.

  15. Document data provenance: Record source, version, access date, and transformations. Future you (and collaborators) will be grateful.

  16. Validate early and often: Check data quality immediately after loading. Validate assumptions throughout analysis. Test edge cases.

  17. Keep raw data raw: Never modify original data files. Save cleaned data separately with clear naming (_cleaned, _processed).

  18. Functions make code reusable: Wrap common operations in functions with clear names and documentation. This reduces errors and improves maintainability.
